인지 부채 감사 — classical-text-browser

감사일 2026-07-04 · 기준 v1.1.4 · 마지막 커밋 6a7fdab(2026-05-19) · 대상: hw725\classical-text-browser

1. 배경 — 왜 이 감사인가

이 프로젝트의 코드 대부분은 AI 에이전트가 작성했다. 총 77,344줄(Python + JS + HTML + CSS)이 존재하지만, 사용자(비개발자 CJK 인문학 연구자)의 이해는 문서에 적힌 지도 수준에 머물러 있고, 실제 영토(코드가 실제로 하는 일)와의 간극이 누적되고 있다. 이 보고서는 유지보수 문서(docs/유지보수문서/04_classical_text_browser.md)가 이미 다루는 내용은 반복하지 않고, 문서가 놓친 보이지 않는 코드 경로·암묵 관례·부수효과와 문서-코드 drift만 다룬다.

2. 직관 — 이 앱을 한 문장으로 다시 보기

겉보기에는 "브라우저에서 고전 문헌을 열람·교정·번역하는 웹앱 하나"지만, 실제로는 최대 3개 프로세스(uvicorn 서버 + OpenAI OAuth 프록시 + 표점 Docker 컨테이너)가 배치파일 한 번으로 함께 기동되고, 결과물은 서고 폴더 안의 문헌별·해석별 독립 git 저장소 수십 개에 흩어져 기록되며, LLM 호출은 5단 폴백 라우터와 10분짜리 결과 캐시를 조용히 통과한다. "버튼 하나"의 뒤에서 무엇이 움직이는지가 이 감사의 핵심이다.

3. 핵심 흐름

텍스트가 원본 이미지에서 주석까지 흐르는 경로와, 그 곁에서 모든 AI 기능이 통과하는 LLM 라우터 경로.

서버 기동 시 start_server.bat이 (a) npx -y openai-oauth 프록시 자동 실행(포트 10531–10540 스캔, Bearer 토큰 oauth-proxy 하드코딩), (b) punctuation-service/.env가 있으면 표점 Docker 자동 기동, (c) 2초 후 브라우저 자동 오픈까지 수행한다. "서버가 안 뜬다"의 원인이 셋 중 어디인지 아는 것이 디버깅의 절반이다.
