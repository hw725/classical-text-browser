# 회고: 고전서지 통합 브라우저 개발 과정

> 이 폴더는 흩어져 있던 설계 결정과 세션 기록을 **회고용으로** 모은 것이다. **원본 문서는 절대 수정하지 않았다.** 모든 항목은 원본 파일로의 링크를 보존한다.
>
> 회고의 목적: 사용자(인문학 연구자)와 Claude(에이전트) 사이의 협업 과정을 되돌아보고, **추후 더 나은 하네스 엔지니어링**에 활용한다.
>
> **범위: D-001 ~ D-050 (2026-02-14 ~ 05-08).** 그 뒤의 결정은 [DECISIONS.md](../DECISIONS.md)에,
> 판별 변화는 [릴리스 노트](../releases/)에 있다. 이 폴더는 그때의 기록이므로 갱신하지 않는다.

## 한 줄 요약

2026년 2월 14일부터 5월 8일까지 약 3개월에 걸쳐 **50개의 명시적 설계 결정(D-001 ~ D-050)** 과 **14개의 세션 문서(Phase 10 ~ 12)** 가 누적되었다. 이 회고는 그 누적물을 통합 타임라인·결정 카탈로그·세션 회고·인터랙션 패턴·하네스 권고로 재배열한 것이다.

## 핵심 관찰 (자세히는 [04_patterns.md](04_patterns.md))

1. **세션 문서의 강한 골격**: 모든 Phase 세션이 `사전 준비 → 설계 요약 → 작업 N → 다음 세션` 구조를 따른다. 사용자가 미리 세션 카드를 채워두고 Claude가 그 안에서 구현했음을 시사한다.
2. **결정의 ID화와 양식 강제**: 모든 결정에 `D-XXX` 영구 ID가 붙고, 6칸 양식(날짜·상태·맥락·결정·근거·트레이드오프)이 거의 깨지지 않는다.
3. **결정 폭발 시점**: 단일 날(2026-02-24)에 14건의 결정이 누적된 날이 있다. 모놀리스 분할(D-027)과 다수의 UX·성능 결정이 동반되었다.
4. **회고 가능성을 의도한 설계**: D-004("층 번호와 작업 순서는 다를 수 있다")처럼, *현재의 모호함을 명시적으로 결정으로 적어두는* 방식이 일관된다.

## 회고 작성 절차 (이 폴더가 만들어진 방법)

1. `docs/` 하위의 모든 `*.md`를 글롭으로 탐색.
2. `DECISIONS.md`를 `## D-NNN` 단위로 분할 → 양식 6칸 추출 → JSON.
3. `docs/sessions/` 14개 파일에서 제목·H2·도입부 추출 → JSON.
4. JSON에서 일자별/카테고리별로 재배열하여 본 폴더의 md 산출.
5. `viewer.html`에서 위 데이터를 클라이언트 사이드로 다시 결합.

원본의 한 글자도 수정하지 않는다. 회고 폴더는 _뷰_ 일 뿐, _스토어_ 가 아니다.
