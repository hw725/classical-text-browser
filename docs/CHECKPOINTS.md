## 2. 주제별 지금 규칙

### 2.1 저장과 층

- **층 번호 ≠ 작업 순서.** 경로 A(L3→L2)·B(L2→L3)·C(손 입력) 모두 유효하다(D-002·D-004).
- **이름**: LayoutBlock(L3 영역) · OcrResult(L2) · 단위(unit, 경계 목록에서 만든 읽기 보기). 「Block」만 쓰지 않는다(D-003·D-093).
- **원본(L1~L4)은 단일 정본, 해석(L5~L8)은 여럿이 병존.** 편성은 원본의 것이다 — 한 문헌의 해석 저장소들은 편성을 공유한다(D-097).
- **경계**: 시작 경계에 id, 끝은 저장하지 않음(같은 깊이 이상의 다음 경계가 끝), 본문은 L4에서 잘라 옴, L4가 바뀌면 `anchor_text`로 재대조(개행 무시), 못 찾으면 `stale`(D-092·D-119 보정 3). 재대조 결과 `l4_commit`만 바뀌면 파일에 쓰지 않는다. 쪼개기는 언제나 한 단 안쪽. 깊이(level)만 의미가 있고 `role`은 화면에서 물러났다(D-092 덧붙임).
- **사람이 만든 것은 서고에, 앱이 들고 다니는 것은 앱에** — API 키(서고 `.env`)·이체자 사전(서고 `resources/`)(D-102·D-104). 앱 폴더에 쓰면 자동 업데이트가 막힌다.
- **JSON 저장은 `write_json_atomic`**(L5~L7 포함), PDF는 `resolve_part_pdf`, `fitz.open()`은 `with`(D-069·D-127). 시험 `test_forbidden_patterns.py`가 지킨다.
- **추정값은 파일에 적지 않는다** — 역할 추정(D-096), bbox 재측정(D-111), 본문(D-092)은 읽을 때 만든다.
- **삭제는 서고 `.trash/`로**(D-023). 마이그레이션은 옛 폴더를 지우지 않고 이름만 바꾼다.

### 2.2 OCR

- **엔진은 `OcrPipeline`으로만**(D-009). 쪽 단위 엔진(NDL 셋·みんなで翻刻)은 **언제나 쪽 전체**에 탐지를 돌리고 행을 블록에 배정, 블록 밖 행은 버린다(D-086). 크롭 경로는 실패 폴백.
- **NDL 업스트림을 그대로 재현한다**: 古典籍-Lite OCR 경로는 모든 탐지를 line_main으로(D-040), PARSeq 색 채널은 엔진마다(D-041), 모델 URL은 태그 고정(AGENTS).
- **스캔 PDF는 내장 이미지 해상도로**(D-087). 쪽 이미지는 `load_page_image_from_pdf`, 회전은 `page_rotation(doc, part, page)` 하나로 읽는다(D-123·D-126).
- **기본 엔진은 문헌 성격을 보지 않는다**(설치된 첫 번째) — 古典籍 Full은 한글을 못 읽는다(AGENTS 인지 부채 7).
- **L3가 없으면 OCR은 200 + `partial`로 조용히 0건**이다 — 호출부가 결과를 확인해야 한다. 추출 모드·권 일괄은 전면 블록을 먼저 만든다(D-055·D-067).
- **배치는 L2가 체크포인트**(D-055). 건너뛰기는 《L2가 있고 지금 L3와 맞을 때》(D-057). 「권 전체 OCR」은 L4를 채우되 사람이 고친 L4는 덮지 않는다(D-115). 쪽 범위와 《된 쪽도 다시》는 독립 스위치.
- **OCR 재실행 직전 백업**(직전 한 단계, L2·L4 pages·corrections를 함께)(D-064·D-065). 교정 저장에는 백업이 없다.
- **사람 교정은 확정본이 다시 써져도 남는다** — 글자 단위 3-way 병합, 겹치면 사람이 이김, 맞춤 0.35 미만이면 병합하지 않고 기록으로, 옮김·못 옮김을 화면에 알림(D-133).
- **OCR 프롬프트는 조립한다**(정책·문헌 지침·블록 종류·자형 주의·앵커), `[?]`로 신뢰도를 낮춘다(D-081). 사고(thinking)는 기본 끔, OCR은 사고문 폴백 끔(D-074·D-083).
- **승급 사다리**: 엔진 → 기계적 선별 → 1단계 교정(사고 끔) → 불합격만 2단계 정밀 판독(사고 켬, 두 단계 일치로 판정) → 사람. 결과는 L4 초안(L2를 덮지 않음), 지문으로 낡음 판정, `[?]`·`□`가 있으면 사람에게(D-082).
- **GPU는 별도 환경 `.venv-gpu`**(uv sync·uv run 금지, python 직접). PaddleOCR은 자식 프로세스 워커 — `.venv-gpu` + torch 차단이면 GPU, 안 되면 `.venv` CPU. onnxruntime-gpu는 CPU판을 빼고 넣는다(D-078·D-091). 글자층의 줄 검출도 같은 워커(`op: detect`)에서 돈다(D-147).
- **화면의 글자층 PDF(단추·권 OCR 뒤 자동)는 교정본(`l4`)으로 굽는다** — 줄 수가 L2와 같으면 L2 줄 상자, 다르면 검출, L4가 없는 쪽은 L2 글. 세로 열은 가로 글줄을 90° 돌려 열 폭 크기로 열을 따라 쓰고, 세로쓰기 쪽의 잉크 검사는 종이 기준 문턱·1.0배(D-147). API 기본값은 `l2` 그대로.
- **신자체 → 정자는 NDL古典籍 엔진 출력에서만, 1:1 확정 글자만**, 기록은 L2 `ocr_config.script_normalize`, 보류 글자는 그 문헌의 승인 쌍으로(D-138). 다른 엔진·L4에는 D-080 그대로.
- **회전은 권의 값 + 쪽 범위**(D-126). 방향은 코드가 잰다(투영 자기상관 + PaddleOCR 점수) — 비전 모델의 방향 답은 투영이 모를 때만.

### 2.3 이체자

- **사전은 지식, 정책은 문헌의 것.** `strict`만 동치, `loose`·`script`는 힌트, 승인은 `documents/{doc}/variant_approvals.json`에만, 사전으로 본문을 고치지 않는다(D-080). 일괄 교정은 사람이 쌍·범위를 정하고 미리 본 뒤 실행 — 실행하면 L4 본문을 고친다(D-122 덧붙임).

### 2.4 편성

- **경계 제안은 저장하지 않는다.** 저장은 편성 탭의 「적용」 하나 — 규칙과 경계를 한 요청으로(경계 먼저), dry_run으로 실제 수를 묻는다(D-088·D-122).
- **규약은 전문에서 센다** — 층계 목차(대조 80%↑면 멈춤, 목차 쪽은 세지 않음) → 시각 → 텍스트 → LLM → 사람(D-117). 코드에 신호 《종류》는 없다 — 발견기 하나(자리 × 접은 문자열)(D-119). 책 이름·어휘를 코드에 넣지 않는다.
- **판식은 좌표에서** — 판심·두주를 빼고 세되 행은 지우지 않는다, 판식이 일정한 책에서만(D-120).
- **규칙 변경은 한 관문** — 사람·통계·LLM 어느 입구든 《바뀐 것》으로 재서 보이고 「적용」으로만 저장, 옮기지 못한 말은 돌려준다(D-121).
- **《바뀐 것》과 「적용」은 같은 함수(`_planApply`)로 센다**(D-121 후속). ③의 바탕은 저장된 경계, 「적용」은 지목한 것만 지운다(`replace=listed` + `drop`).
- **모델은 위치를 만들지 않고 고르기만** — 행 번호로 답하고 코드가 검증(D-125). 사이드바 「자동 트리」는 언제나 LLM 없음(D-117).
- **판정 모델로 고르기**: 규칙 후보로 거르지 않는다(합집합 — 교집합은 문집 재현 0.88→0.18), 목차 문턱은 책에서 뽑고 자기 검증은 따로 선다, 《없음》 선택지 필수(D-129). 본문 판정 대역: accept는 미리 체크, escalate는 체크 해제, reject는 후보 아님. 본문·목차의 주 판정자는 설정의 텍스트 모델(기본 `typesafe/jev-1.14`), 본문 판정에서 실패한 호출만 텍스트 폴백(기본 `perplexity/pplx-decider-v1.2`, 빈 값이면 없음 — 목차 대조는 폴백 없음) — 둘 다 OpenRouter로(D-142). 구도는 D-139(Jev 주·decider 폴백 — decider는 책당 Jev의 약 8배 비용에 정밀 차이 미미). 문턱은 모델 계통으로: Jev 계열 0.85/0.5, decider 계열 0.997/0.69, 잰 적 없는 모델은 Jev 값(`openrouter_decider.judge_family`) — 1.14·v1.2 자체는 재지 않았다.
- **애매한 후보 2차 판정은 붙여 넣기** — 앱은 외부 모델을 부르지 않는다, 결과는 체크 제안뿐, 메모는 서고의 `.escalate_review/`(문헌 git 밖)(D-137).
- 편성 탭은 ①②③ 한 흐름, 단추 넷, 저장 자리 하나(D-122). LLM을 부르는 단추에는 LLM 표지(D-115).

### 2.5 해석(L5~L8)·코어 엔티티

- **해석 편집기 다섯의 《지금 단위》는 사이드바 「내용」 트리가 정한다**(`unit-selected`)(D-096). 트리는 문헌 > 권 > 단위(D-098).
- **L7 계약**: LLM을 기다린 뒤 저장은 파일을 다시 읽어 병합, 주석 좌표는 코드포인트(`_annChars`), 주석·L5·L6 API는 `?part_id=`, LLM 항목은 `parse_llm_items` 하나(D-127).
- **커넥톰 규약**(D-128): 데이터 버전은 출력에 각인(`corpus_version`), 옛 ID는 장부에, 질의 표면 셋, 승격은 개수가 아니라 무게(L4 없으면 《못 잼》·무게 0), 범위는 주소(정렬하지 않음 — 출력 쪽만), 부호는 넷, 조절은 연합 층만, 커넥톰 대조는 판정하지 않음.
- **LLM 결과 되들이기는 새 저장 스키마 없이** L4·경계·L6·L7로 나눠 담고, 노트는 층에서 조립한다(D-131).
- **교환 형식의 정본은 `exchange.schema.json` 하나**(D-100). 원본 쪽에 편성 경계·작업 계획·문헌별 승인까지 담는다
  (2026-10-11 B-013 — 그 전에는 내보냈다 들이면 편성이 통째로 사라졌다). 사전은 받는 서고의 사용자 사전에 **합친다**.

### 2.6 LLM·판정 모델

- **`LlmRouter`가 단일 진입점**, `force_provider`는 인자로(D-010·D-069). 판정 모델은 라우터에 넣지 않는다(《프롬프트 → 글》 계약이 아니다)(D-129).
- **조용한 폴백을 드러낸다** — 과금 방식 표시, 구독 한도를 《무료》로 보이지 않음, 쓴 모델·비용을 결과에(D-056), 닿는가·인증됐는가를 따로(D-058).
- **로컬 서비스는 `127.0.0.1`**(D-109). Ollama 기본 비전은 `kimi-k3:cloud`(글 기본과 같음, D-143), 고르게 한다(D-114).
- **《자동》 기본 모델**: Ollama 텍스트 `kimi-k3:cloud`, ChatGPT 계정 `gpt-6.1-sol`·추론 medium(think=False는 low), 서고 .env `OLLAMA_TEXT_MODEL`·`OPENAI_OAUTH_MODEL`·`OPENAI_OAUTH_EFFORT`와 설정 카드에서 고른다. 기본 모델이 설치·프록시 목록에 없으면 부르지 않는다. 앞 순위 실패는 `LlmResponse.fallback`·서버 경고·응답 머리 `X-CTB-LLM-Fallback`·화면 토스트로(스트리밍·배치는 기록만)(D-143).
- **OpenAI OAuth는 부르기 전에 남은 사용량을 본다**(D-146) — `codex app-server`의 `account/rateLimits/read`(`llm/oauth_quota.py`, 정본은 yoon 사본), 문지기 `OAuthQuotaGuard`(20회·5분마다 재조회, 예비 10%). 예비분 이하·조회 실패·한도 오류(401·402·403·429)·`codex` 없음이면 OAuth를 부르지 않고 남은 순서에서 Claude 쪽(`claude_cli` → `anthropic`)을 맨 앞으로 당긴다(`router.ProviderQueue`). `claude_cli`(`claude -p`, 도구 끔, 텍스트만)는 넘침 전용(`OVERFLOW_ONLY`)이라 평소 순서에 끼지 않는다. Ollama 1순위는 그대로.
- **사고 예산은 답변 예산에 더한다**, JSON은 강제, 잘림은 예외(D-083). Ollama JSON 호출이 사고를 끈 채 JSON이 아니면 사고를 켜 1회 재시도(D-118).
- **판정 모델 클라이언트는 `JevClient` 한 벌을 물려받는다**(Decider·clef·OpenRouter). 키는 제 업체 주소로만 — `KEY_NAMES`·`VENDOR_HOSTS`, 재정의 주소가 다른 업체면 키를 싣지 않는다(D-134·D-136). 상한은 묻기 수로, 상한에 닿으면 폴백(유료)으로 넘기지 않고 멈춘다 — 자동 스캔·편성 본문 판정 둘 다(D-135·D-142).
- **판정 모델은 OpenRouter 목록에서 고른다**(D-142) — 설정 칸 셋(텍스트·텍스트 폴백·이미지), 저장은 앱 설정 `decision_models`, id는 모양 검사 뒤에만 저장, 목록은 OpenRouter `/models?output_modalities=decisions`(실패하면 앱에 든 27개). 직결(TypeSafe·Perplexity·Cloudflare)은 《추가 예정》이라 키가 있어도 쓰지 않는다.
- **이미지 판정은 《고른 이미지 모델(기본 decider v1.2) → kimi-k3》 사슬**(D-142, 옛 clef 사슬 D-135를 대체), 300KB·decider 타일 상한으로 보낸다, 선택 가능 여부는 서버가 `image_available` 한 곳에서. 목록이 텍스트만이라 하는 모델에는 이미지를 보내기 전에 거부한다(D-134 — 옛 Jev가 그랬다. jev-1.14는 목록에 이미지 입력이 있으나 이미지 판정은 재지 않았다).
- **판정 모델 키는 화면에서**(설정 ▸ 판정 모델, 서고 `.env` — 지금은 `OPENROUTER_API_KEY` 하나)(D-134·D-142). 설치 엔진·OAuth 로그인도 화면 단추(D-106·D-107).

### 2.7 화면

- **화면은 《어딜 눌러야 하나》에 답한다** — 한 흐름·단추 최소·저장 자리 하나(D-122). 같은 칸을 두 기능이 쓰면 하나로 합친다(D-132).
- **API 응답 no-store는 미들웨어**(호출부에 안 적음), 정적 파일은 `_NoCacheStaticFiles`(D-055·D-066).
- **화면 라이브러리(PDF.js·d3·onnxruntime-web)는 `static/vendor/`에서** — CDN을 부르지 않는다(오프라인 첫 실행). 브라우저 레이아웃 탐지 모델(.onnx)만은 싣지 않아 처음 한 번 받는다(D-140).
  `.js`·`.mjs`·`.wasm` MIME은 서버가 못박는다(Windows 레지스트리가 `.mjs`를 text/plain으로 줬다)(D-140).
- **`[hidden] { display: none !important }`를 지우지 않는다** — 작성자 CSS가 hidden을 이긴다. jsdom은 이것을 못 잡는다(D-055).
- **전역 JS 이름에는 도메인을 붙인다** — 모듈이 아니라 나중 파일이 이긴다(D-121).
- **《없으면 조용히 넘어가기》 가드는 결함을 숨긴다** — 화면에 알린다(D-063·D-069).
- **신뢰 경계 밖 문자열(파일명·OCR 원문)은 이스케이프**(D-069). 2026-10-11 전수의 남은 자리(B-029)는 고쳤고
  `tests/test_sweep_20261011.py`가 그 자리를 지킨다. 화면이 쓰는 CSS 변수는 모두 정의돼 있어야 한다(같은 시험).
- **탭은 오른쪽 세로 《인덱스》**, 탭을 열 때는 `_switchMode` 대신 탭 버튼 `.click()`(D-057·D-111).
- **UI 폰트는 내려받지 않는다**(브라우저 기본)(D-108).
- 쪽 이동·창 닫기는 미저장 편집을 묻는다(D-133).

### 2.8 설치·배포·업데이트

- **버전 정본은 `pyproject.toml` 하나**(`core.updater.current_version`)(D-072, maintenance §5-7).
- **설치는 `CTB-Setup.exe`(설치만) → 태그 zip → `install.ps1`**(D-113). `--auto`는 바로 가기를 만들지 않는다.
- **켤 때 자동 업데이트**(zip 폴더는 git 사본으로 바꿈, 손으로 고친 파일 있으면 멈춤, `CTB_NO_AUTO_UPDATE=1`)(D-103·D-112). extras는 `.ctb-extras.json`에 적어 uv sync마다 전부 넘긴다(D-106).
- **배포 진입점은 맨 앞에서 `force_utf8_console()`**, `.bat`은 ASCII, `.ps1`은 BOM+CRLF(D-130, AGENTS 표). 이 PC의 `PYTHONUTF8=1`이 cp949 사고를 가린다.
- **설치 5-1은 `ollama list`를 쓰지 않는다**(HTTP `/api/tags` 3초, pull은 시간 제한·핸들 안 물려줌)(D-114 후속).

- 「가벼운 설치」는 없다. CLI와 앱은 같은 패키지(D-070).

### 2.9 검증 규율 (결정마다 되풀이된 교훈)

- **합성 입력만으로 검증하지 않는다** — 파일 형식·외부 엔진을 다루는 코드는 실물로 한 번(D-062·D-068·D-086).
- **시험은 《주장을 깨뜨려 빨간불을 본 뒤에》 적는다** — 표에 시험 이름을 붙이고, 되돌려 실패하는지 본다(D-129, maintenance §3).
- **셀 수 있는 수치는 기계가 센다**(`check_doc_drift`), 줄 수·테스트 건수·과거 기록은 세지 않는다(D-079).
- **《내 PC에서 잘 돌았다》는 증거가 아니다** — 환경변수·설치된 extra·개인 키 파일이 결과를 바꾼다(D-128 구현 기록 6, D-130, D-135 후속).
- **시험이 진짜 외부 서비스를 부르지 않게 막는다** — 이 PC에는 실제 OpenRouter·Cloudflare 키가 있다(D-135·D-136).
- **CI는 빠른 계층만 빈 Windows 서버에서**(`.github/workflows/tests.yml`, `PYTHONUTF8` 끔). 선택 의존이 없어 깨지는 시험은 시험에 건너뜀 조건을 단다(D-144).
- **게이트는 CI 하나** — `main` 보호, PR 필수 검사 `fast`(빠른 pytest·ruff·문서 드리프트), 완료 보고는 CI 결론, 영수증은 PR 전 점검 도구, `.github/doc-sync-ci`로 doc-sync 토큰 면제(D-145).
- **한 곳을 고치면 같은 종류를 전수로 센다**(D-066: 캐시 결함 한 곳 → 47곳).
- **화면 검증은 사용자가 걷는 길로** — 상태를 손으로 넣으면 《단추가 보이는가》를 못 잰다(D-128 사각지대 실측).
