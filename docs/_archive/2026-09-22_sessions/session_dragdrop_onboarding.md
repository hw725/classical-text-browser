# 세션: 드래그 앤 드롭 온보딩 + 아이콘 정비 (explain-diff)

> 2026-07-17. 무엇이 바뀌었는가가 아니라 **왜 이렇게 바뀌었는가**를 남긴다.
> 결정 요약은 [DECISIONS.md D-052](../DECISIONS.md#d-052-드래그-앤-드롭-온보딩--경로-설정-없는-첫-시작).

## 무엇이 바뀌었나 (한 문단)

PDF·이미지·이미지 폴더를 창 어디에나 끌어다 놓으면 곧장 문헌이 만들어진다.
서고가 없으면 기본 서고(`~/Documents/고전서지서고`)가 자동으로 생기고,
doc_id를 입력하지 않아도 서버가 만들어 주며, 제목은 원본 파일명(한자 보존)이
자동으로 채워진다. 아이콘은 파비콘 신설 + 이모지/불명확 글리프를 SVG로 수렴시켰다.

## 세 가지 왜

### 왜 드롭된 파일의 “원본 경로”를 쓰지 않는가

브라우저는 보안상 드롭 파일의 절대 경로를 웹페이지에 주지 않는다. 그런데 이것은
우연히도 이 플랫폼의 설계와 일치하는 제약이다: platform-v7은 원본을 `L1_source/`로
**복사해 불변층으로 격리**한다. 원본 경로를 참조로 잡는 방식(Zotero의 linked file)은
원본을 옮기는 순간 링크가 끊긴다 — 이 프로젝트가 의도적으로 피한 구조다.
그래서 “네이티브 앱으로 다시 만들어야 하나”의 답도 “아니오”였다: 드롭 → 바이트
업로드 → L1 복사로 목표가 100% 달성되고, 정말 네이티브 통합이 필요해지면
pywebview가 현 FastAPI+정적 프론트를 코드 수정 없이 감쌀 수 있다.

### 왜 doc_id 자동 생성을 서버에 두는가

프론트(`_suggestDocIdFromFile`)에도 같은 소독 로직이 있지만, **유일성**은 서버만
판정할 수 있다(기존 `documents/` 디렉토리와의 충돌). 자동 생성을 프론트에 두면
“제안 → 409 거절 → 재입력” 루프가 남는다. 서버가 `기존과 겹치면 _2`를 붙이는
쪽이 드롭 한 번에 끝난다. 한자 파일명 → 빈 후보 → `doc_YYYYMMDD` 폴백은
“연구자가 영문 ID를 지어내야 하는” 기존 최대 마찰의 직접 해소다.
대신 제목은 ASCII 제약이 없으므로 원본 파일명(舊注蒙求攷異提要)을 그대로 살린다 —
소독된 ID보다 사람에게 유용한 것은 제목이다.

### 왜 드롭 즉시 생성하지 않고 확인 화면(Step 2)을 한 번 거치는가

문헌 생성은 git init + 첫 커밋까지 수반하는, 가볍지 않은 부수효과다. 잘못
떨어뜨린 파일이 무확인으로 저장소가 되는 것보다, 파일 목록·제목·(선택) doc_id가
자동으로 채워진 화면에서 “문헌 생성” 클릭 한 번을 요구하는 쪽이 안전-마찰
균형점이다. 즉 기존 6단계가 “드롭 → 클릭 1회”로 줄었고, 마지막 1회는 의도 확인이다.

## 파생 결정들

- **폴더 드롭의 정렬**: `readEntries` 반환 순서는 브라우저 보장이 없다. 이미지
  순서 = 페이지 순서이므로 파일명 numeric 정렬(`img2 < img10`)로 고정했다.
- **폴더 안 잡파일은 조용히 거르고, 최상위 드롭 파일은 거르지 않는다**: 폴더
  순회에서 Thumbs.db를 일일이 알리면 소음이고, 사용자가 직접 떨어뜨린 파일이
  조용히 사라지면 원인을 모른다 — 후자는 “지원 안 함” 메시지를 보여준다.
- **quick-start 위치**: `~/Documents/고전서지서고`. Documents가 없으면 홈 바로 아래.
  이미 있으면 재사용(created:false) — 멱등이라 몇 번 드롭해도 안전하다.
- **아이콘 수렴 방향**: 새 디자인 언어를 만들지 않고, 이미 절반 채택된
  Feather/Lucide 계열 stroke SVG로 수렴. `<option>` 안처럼 SVG가 불가능한 곳은
  텍스트 라벨(`[비전]`)로. 주석 유형 기본 아이콘은 🏷️ 대신 `註` — 이모지의
  OS별 렌더링 편차·tofu 위험을 없애면서 도메인(한문 연구)과 어울린다.

## 자기점검 질문 3개

1. 한자 파일명 PDF를 doc_id 없이 두 번 드롭하면 두 번째 문헌의 doc_id는
   무엇이 되는가? 그 유일성 판정은 프론트와 서버 중 어디서 일어나는가?
2. 이미지 폴더를 드롭했을 때 페이지 순서는 무엇으로 결정되며, 왜 브라우저의
   기본 반환 순서를 믿으면 안 되는가?
3. 서고가 아예 없는 상태에서 드롭하면 어떤 API가 어떤 순서로 호출되는가?
   (힌트: `_ensureLibraryReady` → 어디에 무엇이 생기는가)

  0건이라, 커밋 직전에 하기에는 위험/이득 비가 맞지 않아 의도적으로 보류했다.

- PDF 툴바의 ▲▼(페이지 이동)·↺↻(회전) 글리프는 의미가 통해 교체하지 않았다.
