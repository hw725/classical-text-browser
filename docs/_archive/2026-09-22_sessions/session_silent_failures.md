## 1. 시작 — 「다운받아보니 텍스트 레이어 전혀 없는데」

추출 모드를 다 만들고 릴리스 직전이었다. 사용자가 산출물 PDF를 내려받아
열어 보고 말했다. 드래그가 전혀 안 된다고.

파일을 열어 재 보니 텍스트는 **있었다.**

```
페이지     495 × 694 pt
텍스트  x  12.7 ~ 105.9   (폭의 21%)
        y  558.6 ~ 685.7  (아래쪽 18%)
글자 크기  2.0 ~ 5.5pt     (정상은 9~11pt)
```

495×694pt 종이의 왼쪽 아래 구석에 우표만 하게 박혀 있었다.
`get_text()`로는 14,698자가 멀쩡히 나온다. 로그도 「30줄 제자리」라고 했다.
전부 사실이었다 — 그 30줄이 **어디에 얼마만 하게** 놓였는지는 아무도 재지 않았을 뿐.

## 2. 원인 — 원본 PDF가 걸어 둔 배율

스캐너가 이 논문을 2064×2893 픽셀로 저장하면서, 그 픽셀을 495×694pt 종이에
맞추려고 파일 첫 줄에 배율을 적어 뒀다.

```
0.24 0 0 0.24 0 0 cm      ← q 없이, 되돌리는 Q도 없다
q 2064 0 0 2893 0 0 cm /I0 Do Q
```

`495.36 ÷ 2064 = 0.24`. 정상적인 PDF 관행이다. 다만 그 배율을 `q…Q`로 닫지
않은 것이 이 파일의 특징이었고, **그 뒤에 덧붙이는 모든 것이 함께 0.24배로
줄어든다.**

40pt 자리에 넣은 글자가 9.6pt 자리에, 12pt 글자가 2.88pt로 들어갔다.
정확히 0.24배다.

OCR도 좌표 계산도 배율 환산도 **전부 정상이었다.** 마지막 「PDF에 써넣기」
한 단계에서만 끌려갔다.

```
OCR (원본 배율)  →  좌표 계산  →  PDF에 써넣기
     정상            정상          ← 여기서만 0.24배
```

`page.insert_text()`는 자기 출력을 `q…Q`로 감싸므로 이 영향을 받지 않는다.
그런데 D-062에서 폰트 임베드를 기본으로 바꾸면서 `TextWriter`로 갈아탔고,
**`TextWriter.write_text()`는 감싸지 않는다.**

고침은 한 줄이었다.

```python
if not page.is_wrapped:
    page.wrap_contents()
```

## 3. 왜 테스트가 못 잡았나

`tests/test_text_layer_pdf.py`의 시험용 PDF를 **PyMuPDF로 만들었다.**
깨끗한 내용 스트림이라 이 상황이 아예 생기지 않는다.

18개 시험이 전부 초록이었고, D-055는 「좌표 오차 0.2pt」라고, D-062는
「한자 소실 2자」라고 보고했다. **전부 합성 PDF에서만 참인 값이었다.**

실제 스캔본은 한 번도 열어보지 않았다.

## 4. 패턴 — 이번에 배운 것

고친 뒤 「같은 부류가 더 있나」를 찾으러 저장소 전체를 훑었다. 넷이 더 나왔다.

| 결함 | 증상 | 왜 안 보였나 |
|---|---|---|
| 다권본에서 엉뚱한 권 읽기 | 卷下 OCR 하면 卷上 이미지가 감 | 오류 없이 그럴듯한 결과가 저장됨 |
| 고른 LLM 모델 무시 | 「Claude로」 골라도 기본 순서대로 | 없는 속성에 대입만 하고 호출에 안 넘김 |
| 비원자적 JSON 저장 | 저장 중 죽으면 문헌이 안 열림 | 성공 경로만 시험하면 안 드러남 |
| 파일명 미이스케이프 | 파일명에 스크립트를 넣으면 실행 | 아무도 그런 파일명을 안 써봄 |

그리고 죽은 코드 약 1,000줄 — 비교 모드 880줄, 눌러도 아무 일도 일어나지
않던 「L5 종류」 라디오.

**다섯 가지 모두 자동 테스트가 초록인 채로 살아 있었다.**

### 공통점

전부 **오류를 던지지 않는다.** 그럴듯한 답을 내고, 조용히 넘어간다.

```javascript
if (!container) return;              // 화면 요소가 없어도 조용히
if (typeof f === "function") f();    // 없는 함수를 삼킨다
```

```python
except Exception: pass               # 부분 결과가 «전부»로 반환된다
available = False                    # 엔진이 죽어도 다음 것으로
```

죽은 참조 17건이 **전부** null 가드로 감싸여 있었다. 예외가 나지 않으니
「되지 않는다」가 「없다」처럼 보였다. 그래서 몇 달을 살아남았다.

> **null 가드와 폴백은 실패를 침묵으로 바꾼다.**
> 정말 없어도 되는 것에는 맞고, 반드시 있어야 하는 것에는 틀리다.

## 5. 그래서 넣은 것 — 산출물을 직접 잰다

「몇 줄 넣었다」는 **시도의 기록이지 결과가 아니다.** 원본이 이미지뿐인 이상
텍스트가 제자리인지 확인할 길은 **결과물의 잉크를 재는 것**밖에 없다.

`text_layer_pdf._audit_output()`이 만든 PDF를 **다시 열어** 쪽마다 잰다.

1. 글자 크기 — 5pt보다 작으면 드래그로 잡히지 않는다
2. 텍스트가 덮은 넓이 — 쪽의 2% 미만이면 한 구석에 뭉친 것이다
3. 표본 3쪽은 **그 자리에 실제로 글자가 있는지**(잉크 밀도)까지

실측(박준원 2001, 15쪽): 제자리일 때 쪽 평균의 **2.7~4.8배**.
고침을 빼면 **0.7배**로 떨어지고 검사기가 잡아낸다. 양방향으로 확인했다.

이상이 있으면 내려받기 버튼 옆에 **남는다** — 토스트로 띄우면 몇 초 뒤
사라지는데, 산출물이 서지 관리 도구로 넘어간 뒤에 알면 늦기 때문이다.

### 한계도 적어 둔다

이 검사기는 **이미 아는 모양**만 잡는다. 새로운 종류의 침묵하는 실패는
여전히 사람이 산출물을 봐야 안다. 그래서
[maintenance.md](../maintenance.md) 3장에 「자동 테스트가 못 잡는 것」을
따로 정리했다.
