# v1.3.0 릴리스 노트 (준비 중)

날짜: 2026-09-03 (작업 시작)
범위: v1.2.3 이후 (D-092)

## 한 줄 요약

**글 단위의 정본이 TextBlock에서 «층위 있는 경계 목록»으로 바뀌었습니다.** 단위는 «여기서
시작한다»는 경계 하나로 정해지고, 끝은 같은 층위 이상의 다음 경계가 정합니다. 본문은 저장하지
않고 확정본(L4)에서 잘라 오므로 교감이 자동으로 반영됩니다. 단위의 id는 시작 경계에 붙고, 기존
TextBlock의 id는 그대로 물려받습니다.

## 되돌릴 수 없는 변화 — 있음

- 해석 저장소를 **처음 여는 순간** `core_entities/blocks/*.json`이 `core_entities/boundaries/{문헌}__{권}.json`으로
  옮겨집니다. 옛 파일은 지우지 않고 `blocks_migrated_v1/`로 이름만 바꿉니다(해석 저장소는 Git이라
  되돌릴 수 있습니다). 옮기기는 손실이 없습니다 — id·제목·종류·상태·Work·층위·신뢰도·좌표 캐시가 그대로이고,
  본문은 L4에서 다시 잘라 옵니다.
- v1.3에서 연 서고를 v1.2.x로 열면 단위가 비어 보입니다(경계 목록을 모릅니다). 표점·번역·주석 파일은
  그대로입니다.

## 바뀐 것

### 경계 목록 = 단위의 정본 (D-092)

| 동작 | 이제는 |
|---|---|
| 쪼개기 | 경계 삽입. 앞 단위의 id는 그대로, 새 id는 뒤 단위에 |
| 합치기 | 뒤 경계 삭제. 앞 단위의 id가 남는다. 그 단위를 가리키던 태그가 있으면 알려 준다 |
| 옮기기 | 그 경계의 시작만 바꾼다. 이웃은 저절로 따라온다(재잇기 코드가 사라졌다) |
| 층위 | 1 = 卷·편, 2 = 기사, 3 이상 = 기사 안 조각(문답·협주·연). 층위 n을 손대도 더 얕은 층위의 id는 그대로 |
| 교감 뒤 | 오프셋이 아니라 앵커 글자(그 자리의 앞뒤 글자)로 자리를 다시 찾는다. 못 찾으면 ⚠(stale)로 표시하고 사람이 옮긴다 |

- 화면: 사이드바 「내용」 트리가 층위대로 들여쓰고, 행마다 ▲▼(한 행 옮기기)·L1/L2/L3(층위)·×(앞 단위에
  합치기)가 있으며, 머리에 «경계 넣기»(쪽·행·글자·층위·제목)가 있습니다. 편성 탭의 단위 목록은 경계
  제안 패널이 열리면 접힙니다.
- API: `POST /api/interpretations/{id}/boundaries`(넣기), `DELETE …/boundaries/{id}`(지우기),
  `PUT …/boundaries/{id}`(start·level·title). `entities/text_block` 조회는 경계 목록에서 만든 읽기
  보기이며 관계·태그·표점 편집기가 쓰던 모양 그대로입니다. `text_block/split`은 조각 텍스트로 자리를
  찾아 경계를 넣습니다.
- 스키마: `schemas/core/boundaries.schema.json` 추가(코어 7·전체 20).

### 화면 용어와 트리 (사용자 피드백 뒤, 같은 날)

- 화면의 «TextBlock»을 **단위**로 바꿨습니다. 층위 이름은 **권(L1)·기사(L2)·조각(L3)**. 표점·현토·번역·주석·
  인용 편집기의 블록 선택 항목은 「#3 기사 · 十三日馬觀察談略」처럼 층위와 제목이 보입니다. 내부 이름
  `text_block`·`tb:UUID`는 옛 데이터 참조를 위해 그대로입니다.
- 내용 트리는 권·기사만 한 층으로 세우고, 기사 안 조각(층위 3 이상)은 기사 행의 「조각 N」 배지 아래 접힙니다.
  쪽 배지는 시작 쪽 하나(여러 쪽이면 「14~16쪽」)만 답니다.
- 내용 트리에서 단위를 누르면 **시작 행의 점선이 어느 탭에서나** 보입니다. 전에는 레이아웃 모드에서만
  보이는 오버레이에 그렸습니다.
- 경계 제안 패널에 **목차 감지(LLM)용 모델 선택**이 생겼습니다. 전에는 선택기가 연결돼 있지 않아 늘 «자동»
  (Ollama → 없으면 Gemini 2.5 flash)으로 돌았습니다.
- 경계 제안이 **층위를 미리 추정**합니다. 목차 대응은 목차의 층위(卷 → L1), 나머지는 들여쓰기로 —
  승인된 후보들의 가장 흔한 들여쓰기가 기사(L2), 한 글자 넘게 얕으면 권·편(L1), 깊으면 조각(L3).
  제안 행마다 L1/L2/L3 선택기가 있어 적용 전에 바꿀 수 있습니다.
- **목차가 있는 책은 목차 항목만 기본 선택**됩니다. 날짜·형식 후보는 목차 없는 일기류를 위한 것이라,
  「전부 선택」 단추를 눌러야 넓어집니다.
- 목차 감지(LLM)에서 고른 프로바이더가 죽어 있으면(예: Ollama 서버가 안 떠 있음) 쪽마다 같은 오류를
  되풀이하지 않고 한 번만 알린 뒤 남은 쪽은 규칙으로 갑니다. 오류 문구에 확인할 것(`ollama serve`)이 적힙니다.
- 같은 자리·같은 층위에 경계를 두 번 넣어도 하나만 남습니다. 경계 제안을 두 번 «선택 적용»하자 경계가
  두 벌(77 → 148) 생긴 실측에서 나온 규칙입니다.

### «선택 적용 뒤 사이드바에 안 뜬다» (같은 날 실측·수정)

- 원인은 속도였습니다. 적용이 구간마다 권 전체 확정본을 다시 읽어(208쪽 0.6초) 43구간에 약 30초가
  걸렸고, 그 사이에 «내용 새로고침»을 누르면 아직 저장 전이라 비어 보였습니다. 적용은 행 목록을 한 번
  읽고 경계 파일을 한 번 쓰며 커밋도 한 번만 합니다. 편성 탭이 쪽마다 보내는 단위 요청도 권 텍스트를
  3초 캐시로 되풀이 읽지 않습니다.
- headless Chrome으로 같은 흐름(문헌 선택 → 편성 → 경계 제안 → 선택 적용 → 내용 트리)을 재현해
  43개가 사이드바에 뜨는 것을 확인했습니다.

### 화면 정리 (사용자 피드백)

- 사이드바: 쪽 목록이 한 줄에 하나씩 208행이던 것을 번호 격자(한 줄 일곱 개)로. 모든 섹션 머리를 누르면
  접히고(상태 기억), 서지정보는 기본으로 접힘.
- 편성 탭: 제안 근거를 영어 토큰 대신 한글 칩(날짜·어휘 談草·짧은 행·내려쓰기 / 감점은 붉게)으로. 문턱
  아래 후보는 기본으로 숨기고 「문턱 아래 N개 보기」로 펼침. 목차 줄은 줄바꿈되게.
- 「규칙」에 **해제·참고 텍스트**란. 붙여 넣으면 목차 감지(LLM) 프롬프트에 «참고(사람이 적음, 판단에만
  쓸 것)»로 들어갑니다(`manifest.segmentation_rules.reference_text`, 8,000자까지). 규칙 판별은 이것을
  읽지 않습니다 — 지식은 데이터, 판단은 사람·LLM의 것.

### 자동 트리와 바꿔치기 적용 (사용자 피드백 «Workflowy처럼»)

- **적용은 누적이 아닙니다.** 편성 탭의 「선택 적용」은 «체크 상태가 곧 트리»입니다. 전에 제안으로 만든 경계 중
  이번에 체크가 빠진 것은 지워지고, 손으로 넣은 경계는 남습니다(`replace="proposal"`; 예전처럼 더하기만
  하려면 `"none"`). 11개를 골라 적용했는데 88개가 그대로이던 문제의 답입니다.
- 사이드바 「내용」에 **자동 트리** 단추. 목차 감지 → (원하면 LLM이 해제를 참고해 항목 구조화) → 경계 제안
  (들여쓰기·목차로 층위 추정) → 승인된 것(목차가 있으면 목차 항목만)을 적용까지 한 번에 합니다. 이 권의
  경계는 새로 세워집니다(`replace="all"`, Git으로 되돌릴 수 있음). API `POST …/segmentation/auto`.
- 내용 트리가 **중첩 개요**로 그려집니다. 권 아래 기사, 기사 아래 조각이 들어가고, 자식이 있는 행은 ▸/▾로
  접힙니다. 행마다 ▲▼(한 행 옮기기)·⇤⇥(내어쓰기·들여쓰기 = 층위)·×(앞 단위에 합치기).

### 서버 기동

- **서버를 껐다 켜지 않아도 됩니다.** `start_server.bat`이 `--reload`로 띄워, `src/` 안의 파이썬 파일이
  바뀌면 서버가 스스로 다시 뜹니다(엔진은 다시 읽어 몇 초 걸림). 정적 JS·CSS는 브라우저 새로고침만.
  부모가 고른 서고는 `CTB_LIBRARY` 환경변수로 자식 프로세스에 넘깁니다.
- OpenAI(OAuth) 프록시가 뜨지 않던 문제: 프록시는 10531에만 붙으려 하는데 이 노트북에서는 은행 보안 프로그램
  (AnySign4PC)이 그 포트를 쥐고 있어 `EADDRINUSE`로 죽었습니다. 배치파일이 10531~10540 중 빈 포트를 골라
  `--port`로 넘깁니다.

### 한계

- 내용 트리의 쪽 배지는 더 이상 LayoutBlock id를 갖지 않습니다(단위가 LayoutBlock을 기억하지 않습니다).
  쪽 이동과 시작 행 점선은 그대로입니다.
- 경계 넣기 폼은 쪽·행·글자를 손으로 적습니다. 교정 텍스트에서 글자를 눌러 넣는 편집기는 다음 단계입니다.
- 층위 1(卷) 경계를 목차 대조에서 자동으로 만드는 것은 아직입니다(D-089·D-092 남은 것).
