# v1.3.0 릴리스 노트

날짜: 2026-09-04
범위: v1.2.3 이후 (D-092 ~ D-100)

## 한 줄 요약

**글 단위의 정본이 «경계 목록»으로 바뀌고, 그 목록이 원본 저장소로 내려갔습니다.**
단위는 «여기서 시작한다»는 경계 하나로 정해지고 끝은 다음 경계가 정합니다. 본문은
저장하지 않고 확정본(L4)에서 잘라 오므로 **교감이 자동으로 반영**됩니다. 편성은 이제
문헌의 일이라 **문헌만 고르면 편성까지 갑니다** — 해석 저장소는 표점 탭부터 씁니다.

## 되돌릴 수 없는 변화 — 있음

해석 저장소를 **처음 여는 순간** 마이그레이션 셋이 자동으로 돕니다. 셋 다 옛 파일을
지우지 않고 이름만 바꿔 남기며, 문헌·해석 양쪽에 커밋을 남깁니다(Git이라 되돌릴 수 있습니다).

| 옛 자리 | 새 자리 | 남는 흔적 |
|---|---|---|
| `core_entities/blocks/*.json` | 경계 목록 (D-092) | `blocks_migrated_v1/` |
| `core_entities/boundaries/*.json` | `documents/{문헌}/boundaries/{권}.json` (D-097) | `boundaries_migrated_v2/` |
| `core_entities/works/*.json` | — (Work 엔티티 삭제, D-099) | `works_removed_v1/` |

- 옮기기는 **손실이 없습니다** — id·제목·종류·상태·층위·신뢰도·좌표 캐시가 그대로이고,
  본문은 L4에서 다시 잘라 옵니다.
- 문헌에 이미 경계가 있으면 덮어쓰지 않고, 남의 문헌 파일은 옮기지 않습니다.
- v1.3에서 연 서고를 v1.2.x로 열면 단위가 비어 보입니다(경계 목록을 모릅니다).
  표점·번역·주석 파일은 그대로입니다.

## 업그레이드 안내

**서버를 껐다 켜고 브라우저를 하드 새로고침**(Ctrl+Shift+R)하세요. API 경로가 바뀌었고
옛 JS가 캐시에 남아 있으면 404가 납니다. 서고 쪽에서 손으로 할 일은 없습니다.

## 바뀐 것

### 편성 — 문헌만 고르면 됩니다

- 편성 탭에서 **해석 저장소를 고르지 않습니다.** 문헌·권만 있으면 제안·적용·경계 넣기·
  쪼개기·리셋이 모두 됩니다. 한 문헌에 해석 저장소가 여럿이면 편성을 공유합니다(D-097).
- 편성 탭을 열면 **지금 저장된 경계**가 먼저 보입니다. 사이드바 「내용」과 같은 것을
  가리키므로 어느 쪽에서 눌러도 같은 기사가 골라집니다.
- 사이드바 「내용」은 **문헌 > 권 > 단위**입니다(권이 하나면 권 줄은 생략). 저작이 여럿인
  문집은 층위 1의 «묶음» 경계가 나타냅니다(D-098).
- 「자동 트리」 하나로 목차·해제·들여쓰기·위치를 합쳐 개요를 세웁니다. 행마다 ⇤⇥(깊이)·
  ▲▼(시작 행)·×(앞 단위에 합치기)가 있고, 경계를 옮기기 전에 «어디서 어디로»를 묻습니다.
- **깊이와 역할이 따로입니다** — 깊이는 제한 없고, 뜻은 역할(묶음·기사·조각)이 갖습니다.
  역할이 정해지지 않은 옛 경계는 「(추정)」으로 흐리게 보입니다.
- 쪼개기는 언제나 **기사 «안»**을 문단으로 나눕니다. 별도 기사는 「경계 넣기」에서만 만듭니다.

### 경계를 놓는 방법

- **원본 이미지에서 찍기**가 기본입니다 — 쪽·행을 세지 않고 눈으로 찍습니다(D-094).
  교정 텍스트에서도 찍을 수 있습니다.
- 「卷之一」처럼 **卷 이름으로 끝나는 행은 자동으로 묶음**이 됩니다(D-095).
- 표제 어휘를 모르겠으면 「해제·본문에서 뽑기」가 후보를 찾아 줍니다. 해제는 2만 자가
  넘어도 통째로 넣으면 됩니다 — LLM에 넘길 때만 권별 서술이 있는 데를 골라 간추립니다.

### 해석 편집기

- 표점·현토·번역·주석·인용의 **블록 드롭다운을 없앴습니다.** 사이드바 「내용」에서
  단위를 고르면 다섯이 함께 따라옵니다(D-096).
- 기사가 여러 쪽·쪽 중간에 걸쳐 있어도 **본문 전체**가 뜹니다.

### 화면

- 모드 탭이 **오른쪽 세로 줄**로 갔습니다. 활성 탭을 다시 누르면 오른쪽 패널이 접힙니다.
- 편성 탭의 주 동작은 「경계 제안」 하나이고, 손질 도구는 맨 아래 접이식입니다.
- 시작 행 점선이 PDF 자동 맞춤을 따라갑니다(패널을 접거나 펴도 어긋나지 않습니다).

## 개발자에게

| 무엇 | 바뀐 것 |
|---|---|
| 엔티티 이름 | `text_block` → **`unit`** (D-093). 옛 이름은 한 판 동안 받습니다 |
| 편성 API | `/api/interpretations/{id}/…` → **`/api/documents/{문헌}/boundaries·segmentation·composition·contents`**. 옛 경로는 남기지 않았습니다 |
| 라우터 | `composition.py` 신설(12 라우트). 전체 202 라우트·9 라우터 |
| 코어 스키마 | Work 삭제 → 6종. `Concept.scope_work` → `scope_document` |
| 교환 형식 | 정본이 **`schemas/exchange.schema.json` 하나**가 되었습니다(D-100). 검증기가 그것을 쓰고, 층 안쪽은 각자의 스키마를 `$ref`로 뭅니다. `schema_version`은 1.0 그대로라 옛 스냅샷도 그대로 가져옵니다 |

설계 근거와 대안 검토는 `docs/DECISIONS.md`의 D-092 ~ D-100에 있습니다.

## 확인한 범위

- pytest **957 passed** · ruff · JS 문법 · 문서 드리프트 검사 통과
- 시험용 서고(천진담초 208쪽 · 운양집 103쪽)의 **복사본**으로 실측:
  마이그레이션 셋이 실제로 돌고(경계 46·93개 id 그대로), 편성 탭이 해석 저장소 없이 열리고,
  경계 넣기·고치기·지우기가 **문헌 저장소**에만 커밋을 남기고, 스냅샷 내보내기·검증·가져오기
  왕복이 스키마 위반 0으로 통과합니다. 화면 콘솔 오류 0 · 4xx 0.
- **하지 않은 것**: OCR → PDF 텍스트레이어 경로는 이 판에서 건드리지 않아 다시 돌리지
  않았습니다.

## 알려진 한계

- 卷 감지는 «행 끝이 卷 이름» 규칙이라, 卷 이름이 행 가운데 오는 판식은 못 잡습니다.
  목차 대조나 손으로 넣는 길이 남습니다.
- 「찍기」는 지금 보는 쪽 안에서만 자리를 잡습니다.
- 내용 트리의 쪽 배지는 더 이상 LayoutBlock id를 갖지 않습니다(쪽 이동은 그대로).
- L5~L7 항목은 교환 스키마가 `$ref`로 물지 않습니다 — 저장할 때 각자의 스키마로 검증되고,
  시험이 스냅샷 쪽을 따로 확인합니다(D-100).
