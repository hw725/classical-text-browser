# v1.3.0 — 자동 트리 생성 및 교정

날짜: 2026-09-05
범위: v1.2.3 이후 (D-092 ~ D-104)

## 한 줄 요약

**목차·해제·들여쓰기를 읽어 개요를 자동으로 세우고, 기사의 경계를 눈으로 옮깁니다.**
글 단위는 이제 「여기서 시작한다」는 **경계 하나**로 정해집니다 — 끝은 다음 경계가 정하고,
본문은 저장하지 않고 확정본에서 잘라 오므로 **나중에 교감해도 그대로 따라옵니다.**

## 눈에 띄는 것

### 「자동 트리」 한 번으로 개요가 섭니다

사이드바 「내용」의 **자동 트리** 단추 하나로 목차·해제·들여쓰기·위치를 합쳐
**묶음 > 기사 > 조각**의 개요를 세웁니다.

- 목차가 있는 책은 목차 항목만 고릅니다. 「卷之一」처럼 卷 이름으로 끝나는 행은 묶음이 됩니다.
- 해제(解題)를 「규칙」에 붙여 넣으면 표제 어휘를 찾는 데 씁니다 — 2만 자가 넘어도
  통째로 넣으면 됩니다. 권별 서술이 있는 데만 골라 LLM에 넘깁니다.
- 표제 어휘를 모르겠으면 **「해제·본문에서 뽑기」**가 후보를 찾아 줍니다.

### 경계를 눈으로 놓고, 한 행씩 옮깁니다

- **찍기** — 원본 이미지나 교정 텍스트에서 자리를 누르면 그 자리가 경계가 됩니다.
  쪽·행을 숫자로 세지 않습니다.
- **▲▼** — 시작 행을 한 행씩 옮깁니다. 옮기기 전에 «어디서 어디로»를 보여 주고 묻습니다.
- **⇤⇥** — 깊이를 한 단 넣거나 뺍니다. 깊이는 제한이 없고, 뜻은 **역할**(묶음·기사·조각)이
  따로 갖습니다 — 3단에 있는 기사도 기사입니다.
- **×** — 앞 단위에 합칩니다. 앞 단위의 id가 남으므로 표점·번역이 딸려가지 않습니다.
- 쪼개기는 언제나 **기사 «안»**을 문단으로 나눕니다. 별도 기사는 「경계 넣기」에서만 만듭니다.

### 고른 기사를 다섯 편집기가 따라옵니다

사이드바 「내용」에서 기사를 누르면 **표점·현토·번역·주석·인용**이 함께 그 기사로 맞춰집니다.
편집기마다 있던 블록 드롭다운은 없앴습니다. 기사가 여러 쪽·쪽 중간에 걸쳐 있어도 본문 전체가 뜹니다.

### 문헌만 고르면 편성까지 갑니다

편성은 **원본 저장소의 일**이 되었습니다. 편성 탭에서 해석 저장소를 고르지 않고, 한 문헌에
해석 저장소가 여럿이면 같은 편성을 함께 씁니다. 해석 저장소는 **표점 탭부터** 씁니다.

### 처음 켜면 안내가 뜹니다

- **처음 설정 마법사** — 서고 만들기 · 글자 인식 엔진 · AI 연결을 한 자리에서(D-102).
  설정 ▸ 「처음 설정」으로 언제든 다시 엽니다.
- **고서·일본어 엔진을 단추로 깝니다**(D-106). 터미널에 `uv sync --extra …`를 치지 않습니다.
  앱이 대신 받고 진행을 보여 줍니다. 업데이트가 깔아 둔 엔진을 지우던 문제도 함께 막았습니다.
- **ChatGPT 계정 로그인도 단추 하나**(D-107). 「시작·로그인」을 누르면 프록시가 뜨고 로그인
  창이 열립니다. 로그 파일을 열어 주소를 찾을 일이 없습니다.
- **키를 넣으면 바로 보입니다.** 전에는 새로고침해야 드롭다운에 새 연결이 나타났습니다.
- **모델 목록이 낡지 않습니다.** OpenAI·Claude 모델을 API에서 받아 옵니다 — 손으로 적은
  목록은 gpt-5.2·sonnet-4에서 멈춰 있었습니다. 기본은 gpt-5.4-mini·claude-sonnet-5.
- **API 키를 화면에서 넣습니다.** `.env`를 메모장으로 열 일이 없습니다. 키는 **서고 폴더**에
  저장되므로 앱을 새 판으로 갈아도 남고, 화면·기록 어디에도 키 전체가 나오지 않습니다
  (끝 네 글자만 보여 줍니다). Ollama는 「지금 확인」으로 도는지 바로 봅니다.
- **새 판을 앱 안에서 받습니다**(D-103). GitHub에 들어가지 않아도 됩니다. 고친 파일이 남아
  있으면 받지 않고, 서고 형식을 바꾸는 판은 붉게 알립니다.
- **이체자 사전이 서고로 옮겨졌습니다**(D-104·D-105). 전에는 앱 폴더에 저장돼서, 이체자를
  하나만 넣어도 앱 업데이트가 막혔습니다. 서고마다 다른 사전을 씁니다. 앱은 OpenCC에서 기계로
  만든 힌트 사전만 들고 오고, **손으로 쌓은 사전은 배포본에 들어 있지 않습니다** — 서고의
  「이체자」 화면에서 만들거나 JSON·CSV로 가져옵니다.
- **`install.bat`이 고쳐졌습니다.** 한글이 든 배치 파일을 cmd가 줄 중간부터 읽어
  「'모장으로'은(는) 내부 또는 외부 명령이 아닙니다」가 났습니다. 이제 ASCII 껍데기가
  `install.ps1`(한글)을 부르고, 글자 인식 엔진을 고르는 물음이 붙었습니다.

### 느려서 못 쓰겠던 것

- **쪽 하나를 보려고 PDF를 통째로 받고 있었습니다.** 78.9MB짜리 문헌에서 12쪽을 여는 데
  **81,115KB**를 전송했습니다 — 이제 **1,903KB**입니다(97.6%↓). 첫 쪽이 뜨는 데 0.13초.
  저사양 노트북에서 체감이 가장 큰 자리입니다.
- **첫 화면 7MB 중 5.3MB가 웹폰트 하나였습니다.** UI 폰트를 CDN에서 받지 않고 기기에 있는 것을
  씁니다(D-108) — 첫 화면 전송 **6,998KB → 1,541KB**. 글꼴은 **브라우저에 설정된 기본
  글꼴**을 따릅니다(브라우저 설정 ▸ 글꼴에서 바꿉니다).
- **교정 글씨가 커졌습니다** — 기본 16px → 20px, 도구 바의 「가− 가+」로 14~40px 조절
  (고른 크기는 기억됩니다).

### 그 밖의 화면

- 모드 탭이 **오른쪽 세로 줄**로 갔습니다. 활성 탭을 다시 누르면 오른쪽 패널이 접힙니다.
- 사이드바 「내용」은 **문헌 > 권 > 단위**입니다(권이 하나면 권 줄은 생략).
- **「검증 결과」 패널**이 실제로 동작합니다 — 서고 파일이 제 스키마를 지키는지 검사해
  어긋난 곳을 파일·위치·까닭으로 보여 줍니다. v1.2까지는 「향후 구현」 안내문뿐이었습니다.
- **비고 패널**이 고쳐졌습니다 — 해석 저장소를 골라도 열리지 않던 버그였습니다.

## 되돌릴 수 없는 변화 — 있음

해석 저장소를 **처음 여는 순간** 마이그레이션 셋이 자동으로 돕니다. 셋 다 옛 파일을 지우지 않고
이름만 바꿔 남기며, 문헌·해석 양쪽에 커밋을 남깁니다(Git이라 되돌릴 수 있습니다).

| 옛 자리 | 새 자리 | 남는 흔적 |
|---|---|---|
| `core_entities/blocks/*.json` | 경계 목록 (D-092) | `blocks_migrated_v1/` |
| `core_entities/boundaries/*.json` | `documents/{문헌}/boundaries/{권}.json` (D-097) | `boundaries_migrated_v2/` |
| `core_entities/works/*.json` | — (Work 엔티티 삭제, D-099) | `works_removed_v1/` |

옮기기는 **손실이 없습니다** — id·제목·종류·상태·층위·신뢰도·좌표 캐시가 그대로이고, 본문은
확정본에서 다시 잘라 옵니다. v1.3에서 연 서고를 v1.2.x로 열면 단위가 비어 보입니다
(표점·번역·주석 파일은 그대로입니다).

## 업그레이드 안내

**서버를 껐다 켜고 브라우저를 하드 새로고침**(Ctrl+Shift+R)하세요. API 경로가 바뀌었고 옛 JS가
캐시에 남아 있으면 404가 납니다. 서고 쪽에서 손으로 할 일은 없습니다.

## 개발자에게

| 무엇 | 바뀐 것 |
|---|---|
| 엔티티 이름 | `text_block` → **`unit`**(D-093). 옛 이름은 한 판 동안 받습니다 |
| 편성 API | `/api/interpretations/{id}/…` → **`/api/documents/{문헌}/boundaries·segmentation·composition·contents`**. 옛 경로는 남기지 않았습니다 |
| 라우터 | `composition.py` 신설(12 라우트). 전체 212 라우트·9 라우터 |
| 코어 스키마 | Work 삭제 → 6종. `Concept.scope_work` → `scope_document` |
| 연결 설정 | `GET·POST /api/settings/llm-keys`(서고 .env에 씀, 값은 돌려주지 않음) · `GET /api/settings/ollama` |
| 앱 업데이트 | `GET /api/app/update-check` · `POST /api/app/update`(git pull --ff-only + uv sync) |
| 교환 형식 | 정본이 **`schemas/exchange.schema.json` 하나**가 되었습니다(D-100). `schema_version`은 1.0 그대로라 옛 스냅샷도 그대로 가져옵니다 |

설계 근거와 대안 검토는 `docs/DECISIONS.md`의 D-092 ~ D-104에 있습니다.

## 확인한 범위

- pytest **974 passed** · ruff · JS 문법 · 문서 드리프트 검사 통과
- 시험용 서고(천진담초 208쪽 · 운양집 103쪽)의 **복사본**으로 실측: 마이그레이션 셋이 실제로
  돌고(경계 46·93개 id 그대로), 편성 탭이 해석 저장소 없이 열리고, 경계 넣기·고치기·지우기가
  **문헌 저장소**에만 커밋을 남기고, 스냅샷 왕복이 스키마 위반 0으로 통과합니다.
- 사이드바 여덟 패널을 하나씩 열어 점검 — 콘솔 오류 0 · 4xx 0.
- 처음 설정 마법사 3단계, 키 저장(서고 .env에 쓰이고 응답에 값이 나오지 않는다), Ollama 확인,
  새 판 확인을 실제 화면에서 확인했습니다.
- **하지 않은 것**: OCR → PDF 텍스트레이어 경로는 이 판에서 건드리지 않아 다시 돌리지 않았습니다.

## 알려진 한계

- 卷 감지는 «행 끝이 卷 이름» 규칙이라, 卷 이름이 행 가운데 오는 판식은 못 잡습니다.
- 「찍기」는 지금 보는 쪽 안에서만 자리를 잡습니다.
- 내용 트리의 쪽 배지는 더 이상 LayoutBlock id를 갖지 않습니다(쪽 이동은 그대로).
