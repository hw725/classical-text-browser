# v1.3.0 릴리스 노트 (준비 중)

날짜: 2026-09-03 (작업 시작)
범위: v1.2.3 이후 (D-092~D-095)

## 한 줄 요약

**글 단위의 정본이 TextBlock에서 «깊이 있는 경계 목록»으로 바뀌고, 이름도 «단위(unit)»가 되었습니다.** 단위는 «여기서
시작한다»는 경계 하나로 정해지고, 끝은 같은 층위 이상의 다음 경계가 정합니다. 본문은 저장하지
않고 확정본(L4)에서 잘라 오므로 교감이 자동으로 반영됩니다. 단위의 id는 시작 경계에 붙고, 기존
옛 TextBlock의 id는 그대로 물려받습니다.

## 되돌릴 수 없는 변화 — 있음

- 해석 저장소를 **처음 여는 순간** `core_entities/blocks/*.json`이 `core_entities/boundaries/{문헌}__{권}.json`으로
  옮겨집니다. 옛 파일은 지우지 않고 `blocks_migrated_v1/`로 이름만 바꿉니다(해석 저장소는 Git이라
  되돌릴 수 있습니다). 옮기기는 손실이 없습니다 — id·제목·종류·상태·Work·층위·신뢰도·좌표 캐시가 그대로이고,
  본문은 L4에서 다시 잘라 옵니다.
- v1.3에서 연 서고를 v1.2.x로 열면 단위가 비어 보입니다(경계 목록을 모릅니다). 표점·번역·주석 파일은
  그대로입니다.

## 바뀐 것

### 경계 목록 = 단위의 정본 (D-092)

| 동작 | 이제는 |
|---|---|
| 쪼개기 | 경계 삽입. 앞 단위의 id는 그대로, 새 id는 뒤 단위에 |
| 합치기 | 뒤 경계 삭제. 앞 단위의 id가 남는다. 그 단위를 가리키던 태그가 있으면 알려 준다 |
| 옮기기 | 그 경계의 시작만 바꾼다. 이웃은 저절로 따라온다(재잇기 코드가 사라졌다) |
| 깊이·역할 | 깊이(중첩 단계)는 제한이 없고, 뜻은 역할(묶음·기사·조각)이 갖는다. 깊이 n을 손대도 더 얕은 id는 그대로 |
| 교감 뒤 | 오프셋이 아니라 앵커 글자(그 자리의 앞뒤 글자)로 자리를 다시 찾는다. 못 찾으면 ⚠(stale)로 표시하고 사람이 옮긴다 |

- 화면: 사이드바 「내용」 트리가 층위대로 들여쓰고, 행마다 ▲▼(한 행 옮기기)·L1/L2/L3(층위)·×(앞 단위에
  합치기)가 있으며, 머리에 «경계 넣기»(쪽·행·글자·층위·제목)가 있습니다. 편성 탭의 단위 목록은 경계
  제안 패널이 열리면 접힙니다.
- API: `POST /api/interpretations/{id}/boundaries`(넣기), `DELETE …/boundaries/{id}`(지우기),
  `PUT …/boundaries/{id}`(start·level·role·title). `entities/unit` 조회는 경계 목록에서 만든 읽기
  보기이며 관계·태그·표점 편집기가 쓰던 모양 그대로입니다. `entities/unit/split`은 조각 텍스트로 자리를
  찾아 경계를 넣습니다.
- 스키마: `schemas/core/boundaries.schema.json` 추가, `text_block.schema.json` → `unit.schema.json`(코어 7·전체 20).

### 화면 용어와 트리 (사용자 피드백 뒤, 같은 날)

- 화면의 «TextBlock»을 **단위**로 바꿨습니다. 단위는 역할로 부릅니다 — **묶음·기사·조각**(아래 «깊이와
  역할»). 표점·현토·번역·주석·인용 편집기의 블록 선택 항목은 「#3 기사 · 十三日馬觀察談略」처럼 역할과
  제목이 보입니다. 내부 이름도 `unit`으로 바꿨습니다(아래 «이름 정리»).
- 내용 트리는 권·기사만 한 층으로 세우고, 기사 안 조각(층위 3 이상)은 기사 행의 「조각 N」 배지 아래 접힙니다.
  쪽 배지는 시작 쪽 하나(여러 쪽이면 「14~16쪽」)만 답니다.
- 내용 트리에서 단위를 누르면 **시작 행의 점선이 어느 탭에서나** 보입니다. 전에는 레이아웃 모드에서만
  보이는 오버레이에 그렸습니다.
- 경계 제안 패널에 **목차 감지(LLM)용 모델 선택**이 생겼습니다. 전에는 선택기가 연결돼 있지 않아 늘 «자동»
  (Ollama → 없으면 Gemini 2.5 flash)으로 돌았습니다.
- 경계 제안이 **층위를 미리 추정**합니다. 목차 대응은 목차의 층위(卷 → L1), 나머지는 들여쓰기로 —
  승인된 후보들의 가장 흔한 들여쓰기가 기사(L2), 한 글자 넘게 얕으면 권·편(L1), 깊으면 조각(L3).
  제안 행마다 L1/L2/L3 선택기가 있어 적용 전에 바꿀 수 있습니다.
- **목차가 있는 책은 목차 항목만 기본 선택**됩니다. 날짜·형식 후보는 목차 없는 일기류를 위한 것이라,
  「전부 선택」 단추를 눌러야 넓어집니다.
- 목차 감지(LLM)에서 고른 프로바이더가 죽어 있으면(예: Ollama 서버가 안 떠 있음) 쪽마다 같은 오류를
  되풀이하지 않고 한 번만 알린 뒤 남은 쪽은 규칙으로 갑니다. 오류 문구에 확인할 것(`ollama serve`)이 적힙니다.
- 같은 자리·같은 층위에 경계를 두 번 넣어도 하나만 남습니다. 경계 제안을 두 번 «선택 적용»하자 경계가
  두 벌(77 → 148) 생긴 실측에서 나온 규칙입니다.

### «선택 적용 뒤 사이드바에 안 뜬다» (같은 날 실측·수정)

- 원인은 속도였습니다. 적용이 구간마다 권 전체 확정본을 다시 읽어(208쪽 0.6초) 43구간에 약 30초가
  걸렸고, 그 사이에 «내용 새로고침»을 누르면 아직 저장 전이라 비어 보였습니다. 적용은 행 목록을 한 번
  읽고 경계 파일을 한 번 쓰며 커밋도 한 번만 합니다. 편성 탭이 쪽마다 보내는 단위 요청도 권 텍스트를
  3초 캐시로 되풀이 읽지 않습니다.
- headless Chrome으로 같은 흐름(문헌 선택 → 편성 → 경계 제안 → 선택 적용 → 내용 트리)을 재현해
  43개가 사이드바에 뜨는 것을 확인했습니다.

### 화면 정리 (사용자 피드백)

- 사이드바: 쪽 목록이 한 줄에 하나씩 208행이던 것을 번호 격자(한 줄 일곱 개)로. 모든 섹션 머리를 누르면
  접히고(상태 기억), 서지정보는 기본으로 접힘.
- 편성 탭: 제안 근거를 영어 토큰 대신 한글 칩(날짜·어휘 談草·짧은 행·내려쓰기 / 감점은 붉게)으로. 문턱
  아래 후보는 기본으로 숨기고 「문턱 아래 N개 보기」로 펼침. 목차 줄은 줄바꿈되게.
- 「규칙」에 **해제·참고 텍스트**란. 붙여 넣으면 목차 감지(LLM) 프롬프트에 «참고(사람이 적음, 판단에만
  쓸 것)»로 들어갑니다(`manifest.segmentation_rules.reference_text`, 8,000자까지). 규칙 판별은 이것을
  읽지 않습니다 — 지식은 데이터, 판단은 사람·LLM의 것.

### 자동 트리와 바꿔치기 적용 (사용자 피드백 «Workflowy처럼»)

- **적용은 누적이 아닙니다.** 편성 탭의 「선택 적용」은 «체크 상태가 곧 트리»입니다. 전에 제안으로 만든 경계 중
  이번에 체크가 빠진 것은 지워지고, 손으로 넣은 경계는 남습니다(`replace="proposal"`; 예전처럼 더하기만
  하려면 `"none"`). 11개를 골라 적용했는데 88개가 그대로이던 문제의 답입니다.
- 사이드바 「내용」에 **자동 트리** 단추. 목차 감지 → (원하면 LLM이 해제를 참고해 항목 구조화) → 경계 제안
  (들여쓰기·목차로 층위 추정) → 승인된 것(목차가 있으면 목차 항목만)을 적용까지 한 번에 합니다. 이 권의
  경계는 새로 세워집니다(`replace="all"`, Git으로 되돌릴 수 있음). API `POST …/segmentation/auto`.
- 내용 트리가 **중첩 개요**로 그려집니다. 권 아래 기사, 기사 아래 조각이 들어가고, 자식이 있는 행은 ▸/▾로
  접힙니다. 행마다 ▲▼(한 행 옮기기)·⇤⇥(내어쓰기·들여쓰기 = 층위)·×(앞 단위에 합치기).

### 깊이와 역할을 뗐습니다 (사용자 결정)

- **깊이(중첩 단계)에는 제한이 없고, 뜻은 «역할»이 갖습니다.** 역할은 셋입니다 — **묶음**(卷·集·編),
  **기사**(번역·주석이 붙는 단위), **조각**(기사 안 문단·문답·협주). «조각은 원래 문단인데 3단이 기사인
  책도 있다»는 모순은 숫자에 뜻을 붙인 탓이었습니다. 이제 3단에 있는 기사도 기사입니다.
- 내용 트리 행에 **역할 단추**(묶음/기사/조각)가 붙어 누를 때마다 돌아갑니다. 묶음은 앞에 ▣가 붙어 굵게,
  조각은 ·가 붙어 흐리게 보입니다. ⇥(들여쓰기)는 더 이상 3단에서 멈추지 않습니다.
- 경계 제안 행은 **역할 선택기와 깊이 숫자칸**을 따로 갖습니다. 자동 추정은 목차 상위·얕은 들여쓰기 →
  묶음, 깊은 들여쓰기 → 조각, 나머지 → 기사이고, 적용 전에 바꿀 수 있습니다.
- 역할이 없는 옛 경계는 깊이로 추정합니다(1 묶음, 2 기사, 3 이상 조각). 파일은 고치지 않습니다.
- **역할 단추는 곧바로 반응합니다.** 역할은 단위의 끝도 중첩도 바꾸지 않으므로, 그 행만 다시 칠하고
  저장은 뒤에서 합니다(실패하면 트리를 다시 읽어 되돌립니다). 연타해도 요청은 마지막 값 하나만
  더 갑니다. 화면 반영 1.2초 → 10밀리초 미만(운양집 1책, 경계 90 실측).
- 곁들여 경계 수정(PUT)의 군더더기도 덜었습니다 — 시작이 안 움직였으면 L2 좌표를 다시 재지 않고,
  이미 읽은 권 텍스트를 색인 계산에 물려줍니다. 0.9초 → 0.7초.
- 「규칙」 패널은 **해제·참고 텍스트가 앞**으로 나오고, 표제 어휘·억제 목록·별행 표제 글자수는
  «고급 규칙»으로 접혔습니다. 없애지 않은 이유: 천진담초의 정밀도 0.69 → 0.83이 네 단어(談草·筆談·
  口談·談略) 덕이고, 목차 없는 일기·담초·사행록은 날짜 말고 기댈 신호가 이것뿐입니다.

### 편성 탭에서 옛 흐름을 걷어냈습니다

- **「교정된 LayoutBlock (소스)」 목록과 「합치기」 단추를 없앴습니다.** 「무엇을 고르면 단위가
  되는가」를 묻는 화면인데, v1.3에서 단위는 경계가 정합니다 — 두 흐름이 겹쳐 보였습니다.
  합치기는 사이드바 「내용」 트리 행의 ×(앞 단위에 합치기)가 대신합니다.
- 남은 것은 **자동 편성**(이 쪽의 레이아웃 블록마다 경계 하나 — 글 단위가 잘 안 보이는 문헌의
  출발점)·**쪼개기**(구분선 ===로 나누기)·**리셋**·**경계 제안**입니다.

### 이름 정리 — `text_block` → `unit` (D-093)

- **코드·API·스키마의 이름이 «단위(unit)»가 되었습니다.** v1.3에서 단위의 정본은 경계 목록인데
  조회 이름만 `text_block`으로 남아 «text_block이라 부르는데 실은 경계 목록»이라는 두 겹 이름이
  될 참이었습니다.
- 바뀐 것: 엔티티 종류 `unit`, API `POST …/entities/unit/{from-source,compose,split,reset}`,
  스키마 `unit.schema.json`, 화면 접두어 `unit:`, 요청 필드 `original_unit_id`·`unit_ids`.
- **되돌릴 수 없는 변화는 없습니다.** 저장 형식·파일 이름·id 어느 것도 바뀌지 않았습니다.
  `tb:` 접두어는 애초에 화면 드롭다운에만 쓰이고 저장된 적이 없어(실제 서고에서 0건 확인)
  데이터를 옮길 일이 없었습니다.
- 옛 이름 `text_block`은 **한 자리**에서만 받아 줍니다(`entity.LEGACY_ENTITY_TYPES`) — 목록·조회·
  갱신은 그대로 되고, `entities/text_block/split` 같은 하위 경로는 되지 않습니다. v1.4에서 지웁니다.
- 저장 파일이 단위를 가리키는 필드는 **아직 `block_id`**입니다. 바꾸면 이미 표점·번역을 한 서고의
  파일 이름이 어긋나 작업이 조용히 안 보이게 되므로, 옮기는 스크립트와 함께 따로 합니다
  (`docs/backlog.md` B-003).
- `src/ocr/`의 `text_block`은 NDL OCR의 레이아웃 클래스 이름이라 손대지 않았습니다.

### 원본 이미지에서 찍어 경계 넣기 (D-094, 사용자 제안)

- 사이드바 「내용」의 «경계 넣기»에 **「찍기」** 단추가 생겼습니다. 켜고 원본 이미지에서 자리를
  누르면 **쪽·행·글자가 채워집니다.** 확정본의 몇 번째 행인지 세지 않아도 됩니다.
- 찍자마자 넣지는 않습니다. 그 자리의 글자 여덟 자(「遠近間江水濱廣如」처럼)와 붉은 점선을
  보여 주고, 넣기(＋)는 눌러서 확인합니다. 글자 번호는 «행 길이 × 비율»의 추정이라
  협주·부기가 섞인 행에서 한두 자 어긋날 수 있기 때문입니다.
- 열 사이 여백을 눌렀으면 가장 가까운 행을 잡고 «(행 밖 — 가장 가까운 행)»이라고 알립니다.
- OCR 행 좌표가 없거나 확정본의 행 수가 OCR 행 수와 다른 쪽에서는 «옮길 수 없습니다»라고
  알리고 손으로 적는 길이 남습니다 — 틀린 자리를 조용히 주지 않습니다.
- API: `GET /api/documents/{id}/pages/{n}/position-at?part_id=&x=&y=&image_width=`(라우트 202).

### 卷·표제 어휘·교정 텍스트 (D-095)

- **卷(묶음)을 본문에서 직접 잡습니다.** 목차가 없거나 목차의 卷 항목이 본문과 안 맞아도
  「卷之一」·「第一卷」·「雲養集卷之一」·「附錄」 같은 행이 묶음 경계가 됩니다. 「목차 항목만」
  기본 선택에서도 卷은 남습니다 — 빠지면 트리에 묶음이 하나도 없습니다.
  행 **끝**이 卷 이름이어야 하므로 「卷螺巾車」(제목 속 卷)나 본문 속 卷은 잡히지 않습니다.
  같은 卷 이름이 또 나오면 판심(版心)에 잎마다 적힌 것으로 보고 거릅니다 — 卷 하나가 여러
  조각으로 갈리지 않습니다(운양집 실측: 卷 후보 8개 중 판심 되풀이 4개 탈락).
- **표제 어휘를 뽑아 줍니다.** 「규칙 → 고급 규칙」의 «해제·본문에서 뽑기»를 누르면 해제와
  본문의 짧은 행 예순 개를 LLM에 보여 談草·筆談 같은 후보를 찾습니다. 후보는 칩으로 나오고
  **누른 것만** 규칙 칸에 붙습니다 — 저장은 하지 않습니다.
  표본에 실제로 없는 말은 버립니다(지어낸 어휘로 규칙이 오염되지 않게).
  실측(ollama `qwen3.5:cloud`, 표본 60행): 천진담초에서 `談草`·`談畧`을 4.6초에 찾았고, 판권 줄
  (「京城信紙物商会印行」·전화번호)을 억제 후보로 올렸습니다 — 짧고 頂格이라 형식 신호로는
  표제로 보이던 자리입니다.
- **해제는 통째로 붙여 넣으세요.** 한국고전종합DB 해제 같은 것이 2만 자가 넘어도 됩니다
  (운양집 해제 실측 23,894자). 저장은 통째로 하고, LLM에 넘길 때만 **권별 내용이 있는 데를
  골라** 8,000자로 간추립니다 — 해제는 «생애 → 교유 → 간행과 권별 내용» 순이라 앞에서 자르면
  정작 필요한 권별 서술이 통째로 사라집니다(옛 방식은 「권N」이 하나도 안 들어갔습니다).
  간추린 뒤에도 권1~권15가 남습니다. 칸 밑에 글자수와 무엇이 넘어가는지 표시됩니다.
- **교정 텍스트에서도 자리를 찍습니다.** 「찍기」를 켠 채 오른쪽 교정 텍스트의 글자를 누르면
  그 행·글자가 채워집니다(찍기가 꺼져 있으면 평소대로 교정 대화상자가 열립니다).
- API: `POST /api/documents/{id}/segmentation-rules/suggest`(라우트 203).

### 화면 정리 — 「어지럽다」 (사용자 지적)

단추와 기능이 늘면서 화면이 빽빽해졌습니다. 자리를 먹던 것부터 덜어냈습니다.

- **사이드바**: 208쪽짜리 쪽 격자가 화면의 절반을 먹어 「내용」 트리가 늘 화면 밖에 있었습니다.
  격자에 높이를 주고 스스로 스크롤하게 했습니다(여덟 줄쯤). 내용 트리가 이제 첫 화면에 보입니다.
- **내용 트리의 제목이 「1. …」로 잘리던 것**: 행 도구(▲▼⇤⇥·역할·×)가 보이지 않는 상태로도
  자리를 차지하고 있었습니다. 마우스를 올렸을 때만 오른쪽에 겹쳐 뜨게 했습니다. 제목이 두 배 넓어집니다.
- **«경계 넣기»는 접었습니다** — 「＋ 경계 넣기」를 누르면 펼쳐집니다.
- **편성 탭**: 주 동작은 **「경계 제안」 하나**입니다. 쪽 범위는 같은 줄로 합쳤습니다.
  - 옛 손질 도구(**자동 편성·쪼개기·리셋**)와 단위 목록은 **맨 아래 「단위 손보기」로 내리고 기본으로
    접었습니다.** 여기 있는 것은 «기사 하나 안에서 문단 나누기»와 그 언저리이고, 단위를 세우는 일은
    위의 「경계 제안」과 사이드바 「내용」이 합니다.
  - 단위 카드에서 「p11:? + p12:? + …」처럼 뜻 없는 문자열을 뺐습니다. v1.3부터 단위는 LayoutBlock을
    기억하지 않아 전부 「?」였습니다 — 이제 「11~62쪽」만 보입니다.
  - 제안 행의 신뢰도·역할·깊이·억제를 한 줄로 눕혔습니다. 행 높이 60px → 40px, 한 화면에 보이는
    제안이 6개 → 12개가 되었습니다.

### 서버 기동

- **서버를 껐다 켜지 않아도 됩니다.** `start_server.bat`이 `--reload`로 띄워, `src/` 안의 파이썬 파일이
  바뀌면 서버가 스스로 다시 뜹니다(엔진은 다시 읽어 몇 초 걸림). 정적 JS·CSS는 브라우저 새로고침만.
  부모가 고른 서고는 `CTB_LIBRARY` 환경변수로 자식 프로세스에 넘깁니다.
- OpenAI(OAuth) 프록시가 뜨지 않던 문제: 프록시는 10531에만 붙으려 하는데 이 노트북에서는 은행 보안 프로그램
  (AnySign4PC)이 그 포트를 쥐고 있어 `EADDRINUSE`로 죽었습니다. 배치파일이 10531~10540 중 빈 포트를 골라
  `--port`로 넘깁니다.

### 한계

- 내용 트리의 쪽 배지는 더 이상 LayoutBlock id를 갖지 않습니다(단위가 LayoutBlock을 기억하지 않습니다).
  쪽 이동과 시작 행 점선은 그대로입니다.
- 「찍기」는 지금 보는 쪽 안에서만 자리를 잡습니다. 다른 쪽에 놓으려면 그 쪽으로 옮겨서 찍습니다.
- 卷 감지는 «행 끝이 卷 이름» 규칙이라, 卷 이름이 행 가운데 오는 판식은 못 잡습니다. 그런 문헌은
  목차 대조나 손으로 넣는 길이 남습니다(D-095).
