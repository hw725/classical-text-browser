# v1.4.0 — 책의 규약을 스스로 찾고, 편성을 한 흐름으로

날짜: 2026-09-10 · 범위: v1.3.0 이후

되돌릴 수 없는 변화 — 없음. 저장 형식은 칸이 늘었을 뿐(권 회전, L2·L3의 회전 도장, 편성 규칙
`segmentation_rules`의 신호 스위치·어휘·꼴·판심 칸)이고, 빠진 키는 기본값으로 읽으므로 옛 파일은 그대로 읽힙니다.

**편성 탭이 ①②③ 세 단계 한 흐름이 되었고, 책마다 다른 글의 시작 표지를 코드가 아니라 전문에서
찾습니다.** 옆으로 스캔된 책은 회전을 저장해 OCR하고, くずし字 고문서용 OCR 엔진이 하나 늘었습니다.

## 설치 (Windows)

1. 이 페이지 아래 **Assets**의 **`CTB-Setup.exe`**를 받아 두 번 누릅니다.
2. 창에서 설치 폴더와 글자 인식 엔진을 고르고 「설치」 — 이번 판부터 **4) くずし字 엔진**을 함께 고를 수 있습니다.
3. 「지금 실행」. 다음부터는 바탕화면의 **「고전서지 브라우저」** 아이콘으로 켭니다.

- 이미 깔린 PC는 `start_server.bat`을 켜면 저절로 새 판을 받습니다(설정 ▸ 앱 업데이트에서도).
- macOS·Linux는 zip을 풀고 `./install.sh`.

## 편성 — 한 흐름

- **① 이 책은 어떻게 나뉘나** — 탭을 열면 전문을 세어 «찾은 규약: 기호 「○」 217회»처럼 한 줄로 답합니다.
  사람이 책을 보는 순서(목차 → 시각 신호(내려쓰기·짧은 행) → 텍스트 패턴(되풀이되는 기호·행 첫머리·행 끝의 글) →
  LLM → 사람)를 따르고, 판심·두주처럼 종이의 규약은 좌표로 가려 뺍니다. 아는 것을 한 줄 쓰면(«목차와 제목이 없다. 기사는
  ○ 뒤의 날짜로 시작한다») 규칙 칸으로 옮겨 주고, 옮기지 못한 말은 바꿔치기하지 않고 그대로 알려 줍니다.
- **② 규칙 고르기** — 센 규약 후보가 횟수·보기와 함께 체크박스로 섭니다. 체크한 것이 이 책의 규칙입니다.
- **③ 후보 고르기** — 체크 = 경계가 될 것. 행을 눌러 고르고 Shift로 범위, Ctrl로 하나씩 골라 역할·깊이를
  **한꺼번에** 바꿉니다. 규칙을 바꿔 다시 세우면 «바뀐 것 — 새로 잡히는 자리 N · 빠지는 자리 M»이 먼저 보입니다.
- **「적용」 하나**가 규칙과 경계를 함께 저장합니다. 지울 경계가 있으면 실제 수를 묻습니다.
- 모델을 부르는 것은 ①의 「말로 넣기」·「더 묻기…」 둘뿐이고, 어느 모델이 도는지는 그 옆 「모델」이 정합니다.
  이미지가 아니라 텍스트만 보냅니다(「시작 표지 묻기」는 표본 범위를 시작 자리 80줄 / +앞뒤 한 행 / 6쪽 / 권 전체
  중에서 고르고, 고르면 몇 줄·몇 자인지 미리 보입니다). 「더 묻기」의 답은 전문에서 되풀이되는 것만 받고,
  「말로 넣기」는 옮긴 어휘가 전문에 몇 번 나오는지를 붙여 보입니다(0번이면 이 책의 말이 아닙니다).

## 원본을 다루는 방식

- **회전 저장** — 옆으로 스캔된 책은 ↺↻로 세운 뒤 「저장」. 그 권의 OCR·레이아웃·판독·텍스트 레이어 PDF가
  모두 세운 이미지를 씁니다. 이미 있는 OCR·레이아웃 결과가 있으면 «N쪽은 좌표계가 어긋나므로 다시 돌려야
  합니다 (지우지는 않습니다). 계속할까요?»라고 묻고, 저장 뒤 «N쪽은 다시 OCR해야 합니다»라고 알립니다.
- **みんなで翻刻OCR** — 붓으로 흘려 쓴 초서·변체가나 고문서용 엔진(橋本雄太, CC BY 4.0; Python 이식 honkoku-ocr-py, MIT).
  설치 4번 선택지(모델 약 290MB를 설치 때 미리 받음) 또는 설정 ▸ 처음 설정 ▸ 글자 인식의 「설치」(첫 사용 때 받음). 한글은 못 읽습니다.
- **판식을 좌표에서** — 판심·두주·반엽 행 수를 좌표에서 재고, 서지의 KORMARC 판식(「10行20字」)과 맞대어 검산합니다.
- **교정 탭 「일괄」 «실행»이 실제로 본문을 고칩니다** — 전에는 기록만 남기고 확정본은 그대로였습니다
  («실행»은 「미리보기」를 누른 뒤에 켜집니다).
- **작은 고침** — 「단위 손보기」가 늘 비어 있던 것(해석 저장소를 보고 있었음), 「표제 어휘 뽑기」가 `:cloud` 모델
  이름을 잘라 보내 Ollama 404가 나던 것, 앵커 재대조가 행갈음을 넘고 겹쳐 놓기·반쯤 적용을 거절하는 것,
  사고를 끈 JSON 호출이 JSON이 아니면 사고를 켜 한 번 더 시도하는 것(glm-5.3:cloud), Ollama 후보에 텍스트용
  `glm-5.3:cloud` 추가.
- **교정 탭이 확정본을 저절로 채웁니다** — 확정본이 비어 있는 쪽을 열면 OCR 결과가 들어오고, 이미 고친 글은 덮지
  않습니다. 「OCR 채우기」 단추는 없앴습니다(글을 다 지우고 저장하면 다음에 열 때 다시 채워집니다).
- 90° 회전에서 가로·세로 맞춤이 어긋나고 왼쪽이 잘리던 것을 고쳤습니다. 읽기 보조선은 가로 → 세로 → 끔.

## 새 판으로 갈아타기

- `start_server.bat`을 켜면 저절로 받습니다. 열어 둔 앱에서는 설정 ▸ 앱 업데이트 ▸ 「받기」, 그 뒤 서버를 껐다 켭니다.
- v1.3.0 이전 판을 zip으로 깔았던 PC는 위 `CTB-Setup.exe`를 한 번 돌립니다(같은 폴더 선택).

## 주의

- 회전을 저장하면 그 권의 옛 OCR·레이아웃은 좌표계가 달라 OCR이 다시 잡으라고 합니다(지우지는 않습니다).
  옛 레이아웃이 남은 쪽은 「권 전체 OCR」에서 «다른 회전에서 만들어졌습니다»로 실패로 집계됩니다 — 레이아웃을
  다시 잡거나 지운 뒤 돌리세요.
- みんなで翻刻OCR은 CPU에서 한 쪽에 1분쯤 걸립니다(실측 85초). GPU가 없으면 권 전체보다 쪽 단위로 쓰세요.
  CUDA가 있으면 `HONKOKU_OCR_DEVICE=cuda`(onnxruntime-gpu가 있으면 자동). 모델 저장 위치는 `HONKOKU_OCR_MODELS`.

## 아직 안 되는 것

- 협주(註雙行)는 아직 가르지 못합니다.
- 회전 저장 뒤에도 옛 레이아웃이 화면 오버레이에 그대로 그려질 수 있습니다 — «다시 OCR»을 따르면 사라집니다.

설계 근거는 `docs/DECISIONS.md` D-115 ~ D-124.
