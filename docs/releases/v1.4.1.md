# v1.4.1 — 남의 PC 에서 죽던 자리들

날짜: 2026-09-22 · 범위: v1.4.0 이후 · **되돌릴 수 없는 변화 없음**(저장 형식 그대로)

## 설치

- Windows — 아래 **Assets** 의 `CTB-Setup.exe` → 두 번 누르기 → 폴더·엔진 고르기 → 「설치」 → 「지금 실행」
- 다음부터는 바탕화면 **「고전서지 브라우저」** 아이콘
- 이미 깔린 PC — `start_server.bat` 을 켜면 저절로 새 판을 받습니다
- macOS·Linux — zip 을 풀고 `./install.sh`

## 고친 것

### 설치·첫 실행

- **설치 직후 「지금 실행」이 막히던 것** — uv 가 없던 PC 에서 설치에 성공하고도
  「uv is not installed」로 끝났습니다. 설치 프로그램이 방금 깐 uv 를 못 보던 탓입니다
- **환경 진단(`doctor.bat`)이 죽던 것 둘**
  - cp949 콘솔에서 `—`·`«»`·`✓` 를 찍다 `UnicodeEncodeError` — **환경이 이상할 때 누르는
    것**이라 가장 필요한 순간에 오류 화면이 떴습니다
  - 설치가 중간에 깨진 PC 에서 `ModuleNotFoundError`
- **설치 프로그램을 처음부터 끝까지 실제로 돌려 확인** — 내려받기 → 압축 풀기 →
  의존성 설치 → 모델 미리 받기 → 앱 켜기

같은 cp949 자리를 전부 찾아 막았습니다:

| 어디 | 언제 죽었나 |
|---|---|
| `scripts/doctor.py` | `doctor.bat` 을 누를 때 |
| `scripts/warmup_paddle.py` | 설치 5단계에서 **모델을 못 받았다는 설명을 찍으려다** |
| `src/ocr/paddle_worker.py` | PaddleOCR 자식 프로세스 |
| `src/core/updater.py` | 새 판 확인 |
| `src/app/__main__.py` | 코드가 바뀌어 서버가 다시 뜰 때 |
| `CTB-Setup.exe` | 설치 프로그램의 `--help`·창 경로 |

### 쓰다가 막히던 것

- **영문 이름 PDF 한 장을 끌어다 놓으면 거절** — `report.pdf` 하나를 넣어도
  「같은 이름의 PDF 가 두 번 포함되었습니다」. 서버가 파일 이름으로 만든 문헌 ID 가
  올린 파일 이름과 같아져 **자기 자신과 충돌**했습니다. 한글 이름은 겪지 않아
  오래 드러나지 않았습니다
- **한글 제목 해석을 JSON 으로 내보내면 오류** — 내려받기 이름에 한글을 그대로 넣었는데
  웹 표준상 그 자리는 영문만 됩니다. 이제 표준 방식(RFC 5987)으로 한글 이름이 그대로 내려옵니다
- **그 한글 이름이 화면까지 오지 않던 것** — 서버를 고쳐도 화면이 영문 대체 이름을 써서
  `interpretation_20260922.json` 로 저장됐습니다. 이제 `천진담초_20260922.json`
- 이 저장소의 문헌은 제목이 거의 다 한글이라, 사실상 늘 실패하던 기능입니다

## 개발자용

- `src/core/console.py` — 콘솔 고정을 한 곳에 모았습니다. 배포 진입점은 여기를 부릅니다
- 이 종류가 다시 들어오지 못하게 **검사 열**을 붙였습니다
  - 배포 진입점이 고정을 **먼저** 부르는가 (있는가가 아니라 순서)
  - CJK 텍스트 계약(파일 인코딩·콘솔·정규식) · `.ps1` 의 UTF-8 BOM
  - 설치 파일이 받는 판과 `pyproject` 의 판이 같은가
  - 영문 이름 PDF 한 장을 받는가 (이미지가 함께 올 때의 이름 예약은 그대로)
  - 내려받기 헤더가 latin-1 로 인코딩되는가 · **사람이 받는 이름에 한글이 들어가는가**
  - 설치 프로그램이 띄우기 전에 PATH 를 다시 만드는가
  - 진단이 경로를 등록한 **뒤에** 모듈을 부르는가
- **「서고가 설정되지 않았습니다」를 500 → 409** (131곳). 서고가 없는 것은 처음 켠 사람의
  정상 상태이고, 500 은 서버 잘못이라는 뜻이라 진짜 오류가 묻힙니다
- **`ruff` 64건 → 0.** v1.4.0 태그는 0건이었는데 그 뒤 86커밋 동안 ruff 를 부르는 관문이
  없어 조용히 쌓였습니다. 시험의 기준선은 비어 있고, 비면 「어느 파일이든 0」입니다
- Ollama 의 thinking 폴백을 `CLAUDE.md`·`DECISIONS.md` 가 「어디에도 없다」·「어떤 경우에도
  두지 않는다」고 잘못 적고 있었습니다. 막으려던 것은 OCR 이 사고문을 판독 결과로 저장하는
  것이었는데 전역 금지처럼 적혀 있었습니다 — 범위를 밝혀 바로잡았습니다
