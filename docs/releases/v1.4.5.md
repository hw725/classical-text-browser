# v1.4.5 — ChatGPT 계정 남은 사용량 확인 · 넘치면 Claude로 · 글자층 PDF(교정 반영·세로쓰기)·.hwp 글자 손실 수정

날짜: 2026-10-28 · 범위: v1.4.4 이후 · **되돌릴 수 없는 변화 없음**(서고 파일·저장 형식은 바뀌지 않습니다)

## 설치

- Windows — 아래 **Assets** 의 `CTB-Setup.exe` → 두 번 누르기 → 폴더·엔진 고르기 → 「설치」 → 「지금 실행」
- 이미 깔린 PC — `start_server.bat`을 켜면 저절로 새 판을 받습니다(받지 못하면 까닭을 알립니다)
- macOS·Linux — zip을 풀고 `./install.sh`

## 바뀜

- **ChatGPT 계정(OpenAI OAuth)은 부르기 전에 남은 사용량을 확인합니다** (D-146). `codex /status`와 같은 값을 `codex` CLI로 읽어, 5시간·7일 창 중 적게 남은 쪽이 10% 이하이거나, 확인에 실패하거나, 한도 오류(401·402·403·429)가 나면 OAuth를 더 부르지 않습니다. 확인은 20회 호출마다 또는 5분마다 다시 합니다. 확인 자체는 사용량을 쓰지 않습니다.
- **그때 남은 일은 Gemini가 아니라 Claude가 이어 받습니다** (D-146). 이 PC에 로그인된 Claude Code(`claude`)가 있으면 그 로그인 계정으로, 없거나 이미지 작업이면 Anthropic 키로 갑니다. 둘 다 없으면 전처럼 다음 순위로 넘어갑니다. 넘긴 사유는 폴백 알림에 「OAuth 남은 사용량 …」으로 나옵니다. 「모델」 칸에서 OAuth 모델을 직접 골랐을 때도 Claude로 넘기고, Claude도 처리하지 못하면 사유를 모두 알립니다.
- **`codex` CLI가 없는 PC도 OAuth 자리에서 Claude를 먼저 씁니다** — 남은 사용량을 확인할 수 없어서입니다. Ollama가 1순위인 것은 그대로입니다.
- Claude Code 공급자는 이렇게 넘칠 때만 쓰이고 평소 폴백 순서에는 끼지 않습니다. 쓸 모델을 고정하려면 서고 `.env`에 `CLAUDE_CLI_MODEL`을 적습니다.

## 고침

- **글자층 PDF가 끝 줄을 잃던 것** (B-081). 잘라 보이기(CropBox)가 걸린 쪽에서 글자층이 아래로 밀려 끝 줄이 쪽 밖으로 나가 빠졌습니다. 회전된 쪽도 맞게 얹힙니다.
- **글자층 PDF에서 옛한글 자모·확장 A 한자 일부(䟽 등)·㊞가 빠지던 것** (B-082·B-084). 기본 글꼴에 없는 글자는 설치된 한컴 돋움·맑은 고딕으로 넣고(한 음절은 한 글꼴로), 어느 글꼴에도 없으면 경고합니다. 다른 글꼴을 쓰려면 환경 변수 `CTB_TEXT_LAYER_FALLBACK_FONTS`에 글꼴 파일 경로를 적습니다.
- **.hwp를 읽을 때 확장 B 한자와 구결자(PUA)가 사라지던 것** (B-080). 본문·각주 어디서나 남습니다. .hwpx는 원래 문제가 없었습니다.
- **화면에서 만든 글자층 PDF에 검수에서 고친 글자가 빠지던 것** (B-085). 추출 패널의 「텍스트 레이어 PDF 다시 만들기」와 권 전체 OCR 뒤 자동으로 만드는 PDF가 이제 교정한 글로 만들어지고, 글자는 OCR이 찾은 줄 자리에 그대로 놓입니다. 아직 확정본이 없는 쪽은 OCR 결과를 넣고 그 쪽 번호를 알려 줍니다. 이미 만든 PDF는 단추를 한 번 더 눌러야 바뀝니다.
- **세로쓰기 문헌의 글자층이 열마다 아주 작은 가로 글줄로 열 아래 끝에 몰리던 것** (B-085). 이제 글이 열을 따라 위에서 아래로, 열 폭에 맞는 크기로 놓여 드래그·검색했을 때 제 열이 잡힙니다.
- **GPU 환경(`.venv-gpu`)에서 글자층의 줄 위치 찾기가 늘 실패하던 것** (B-085). 줄 위치 찾기도 PaddleOCR 작업 프로세스에서 돌아, 교정에서 줄을 합치거나 나눈 쪽도 줄 자리를 찾습니다. 세로쓰기 쪽은 열 단위로 찾습니다.

---

- Changed: Before calling the ChatGPT account (OpenAI OAuth), the app now reads the remaining usage (the same numbers as `codex /status`, needs the `codex` CLI). If the smaller of the 5-hour and 7-day windows is at or below 10%, the check fails, or a limit error comes back, the work goes to Claude instead of Gemini — the logged-in Claude Code CLI (`claude`) for text, an Anthropic key otherwise or for images. PCs without `codex` take the same path. Ollama stays first. The Claude Code provider is used only for this overflow; set `CLAUDE_CLI_MODEL` in the library `.env` to pin its model.
- Fixed: Text-layer PDFs lost their last lines on cropped pages, and dropped Old Hangul jamo and some rare characters missing from the embedded font (they now use an installed fallback font, or are reported).
- Fixed: Reading .hwp files dropped CJK Extension B characters and gugyeol PUA characters.
- Fixed: Text-layer PDFs made from the app (the extract panel button and the automatic run after a whole-volume OCR) now use the corrected text, placed on the OCR line positions; pages without corrected text get the OCR text and are listed in a warning. Vertical (top-to-bottom) columns are now laid along the column at column width instead of as a tiny horizontal line, and line detection no longer fails in the GPU environment.
