# v1.2.0 릴리스 노트

날짜: 2026-07-26
범위: v1.1.5 이후 20개 커밋 (D-055 ~ D-069)

## 한 줄 요약

근현대 논문 스캔본을 **끌어다 놓고 → OCR → 검색되는 PDF**까지 한 화면에서
끝내는 **추출 모드**를 더했습니다. 고서 교감 흐름은 그대로입니다.

## 먼저 읽어 주세요 — 다시 만들어야 하는 파일이 있습니다

**v1.2.0 이전에 만든 텍스트 레이어 PDF는 모두 쓸 수 없습니다.**
텍스트가 쪽 구석에 2pt 크기로 박혀 있어 드래그도 검색도 되지 않습니다
(D-068). 서고를 열고 「텍스트 레이어 PDF 다시 만들기」를 한 번 눌러 주세요.

앱을 켜 둔 채로 갱신했다면 **서버를 껐다 켜야** 고침이 적용됩니다.

## 추출 모드 — 논문 한 편을 위한 화면 (D-055 · D-057 · D-060)

기존 화면은 고서를 위한 것입니다. 상단 작업 탭 10개, 8층 데이터 모델,
원본·해석 이중 저장소 — 근현대 논문에서 텍스트만 뽑으려는 사람에게는
전부 통과 의례입니다. 추출 모드는 그 의례를 걷어냅니다.

- 문헌을 열면 **텍스트 레이어가 있는지 먼저 진단**합니다. 이미 있으면
  OCR 없이 바로 가져오고, 스캔본이면 OCR 경로로 안내합니다.
- 레이아웃을 사람이 잡지 않습니다. **쪽 전체를 한 블록으로** 자동으로
  잡아 저장합니다(D-067). 이상하면 레이아웃 탭에서 고치면 됩니다.
- 권 전체를 **한 번에** OCR 합니다. 이미 끝난 쪽은 건너뛰므로 중단해도
  이어서 돌아갑니다.
- 표점·현토·이체자·편성 탭이 숨습니다. 서고 백업·Git 이력 등 교감용
  설정도 함께 정리됩니다.

## 검색되는 PDF — 이번 판의 핵심 수정 (D-055 · D-062 · D-068)

원본 이미지 위에 **보이지 않는 텍스트**를 얹어 Ctrl+F·복사·서지 도구
연동이 되는 PDF를 만듭니다. 원본(`L1_source/`)은 읽기만 하고 결과는
`exports/`에 새 파일로 나갑니다.

- **줄 위치 검출**로 텍스트를 실제 글자 자리에 놓습니다. 좌표를 주지 않는
  LLM Vision 엔진에서도 형광이 원문 위에 뜹니다.
- **폰트를 임베드**합니다. 임베드하지 않으면 표준 CID 폰트에 없는 한자가
  조용히 사라졌습니다 — 실측에서 51종 130자(`郎` 27회, `儂` 22회)가
  누락됐습니다(D-062).
- **원본이 남긴 좌표 변환을 끊습니다.** 이것이 이번 판에서 고친 가장 큰
  결함입니다(D-068). 아래 「고친 결함」 참조.
- **만든 PDF를 앱이 다시 열어 잽니다.** 글자 크기, 텍스트가 덮은 넓이,
  그리고 표본 3쪽은 **그 자리에 실제로 글자가 있는지**(잉크 밀도)까지
  확인합니다. 이상이 있으면 내려받기 버튼 옆에 남습니다.
- 내려받는 파일 이름은 **원본 논문 파일명 그대로**입니다 —
  `저자_연도_제목.pdf` 규약이 깨지지 않습니다.

## 쪽별 검수 — 만들기 전에 확인한다 (D-057 · D-058)

- 「쪽별 검수」에서 **모든 쪽의 결과를 한눈에** 봅니다. 글자 수·줄 수와
  미리보기가 나오고, 빈 쪽이나 짧은 쪽에 표시가 붙습니다.
- 행을 누르면 그 쪽으로 이동하고 쪽 범위에 들어갑니다. 「대조」·「영역」
  버튼으로 교정 탭·레이아웃 탭에서 바로 확인할 수 있습니다.
- 확인한 쪽을 체크해 두면 PDF를 만들기 전에 **덜 본 쪽을 알려 줍니다.**
- LLM을 어느 모델로 몇 번 불렀고 얼마가 나갔는지 화면에 표시합니다(D-056).

## OCR 다시 돌리기와 되돌리기 (D-057 · D-064 · D-065)

- 레이아웃을 고친 쪽을 **기계가 찾아냅니다.** 그 쪽만 다시 돌립니다.
- 다시 돌리기 **직전 상태로 되돌리는** 버튼이 있습니다. 새 결과가 이전만
  못할 때 쓰는 수단입니다 — OCR 결과와 교정 텍스트를 함께 되돌립니다.
- 되돌리기는 로컬 JSON 백업입니다. Git 이력과 무관합니다.

## 설치와 실행 (D-059 · a3894c2 · e304f77)

- **Python 3.12** 기준입니다(paddlepaddle 휠이 cp312까지). 3.10·3.11도
  그대로 지원합니다.
- 기본 설치에 **PaddleOCR**이 들어갑니다. 일본 고전적용 NDL 계열과
  GPU 스택은 extras로 분리했습니다 — `japanese`, `classical`, `classical-gpu`.
- **한 줄 명령**을 더했습니다. 서고를 미리 만들 필요가 없습니다.

  ```
  ctb ocr 논문.pdf
  ctb ocr 논문폴더/
  ```

- `opencv-contrib-python`과 `opencv-python-headless`가 같은 `cv2`를
  제공해 한쪽을 지우면 남은 쪽까지 깨지던 충돌을 해소했습니다.

## 문헌 구조 (D-061)

- 만든 뒤에도 **권을 더할 수 있습니다.** 사이드바 문헌 옆 `＋`.
- 단권 문헌은 트리에서 권 단계를 건너뛰고 쪽이 바로 나옵니다.
- 문헌 병합(따로 등록한 卷上·卷下 합치기)은 되돌릴 수 없는 작업이라
  실제 사례를 보고 설계하기로 하고 미뤘습니다.

## 고친 결함

### 텍스트 레이어가 0.24배로 박혔다 (D-068) ★

내려받은 PDF에서 드래그가 전혀 되지 않았습니다. 텍스트는 **있었지만**
495×694pt 쪽의 왼쪽 아래 구석에 2.0~2.9pt 크기로 들어가 있었습니다.

원인은 원본 스캔 PDF입니다. 스캐너가 2064픽셀을 495pt 종이에 맞추려고
파일 첫 줄에 `0.24` 배율을 적어 두는데, 그것을 되돌리는 표시가 없었습니다.
그 뒤에 덧붙이는 모든 것이 함께 0.24배로 줄어듭니다.

OCR도 좌표 계산도 정상이었고 **마지막 써넣기 한 단계에서만** 끌려갔습니다.
폰트 임베드를 기본으로 바꾸면서(v1.1.5의 D-062) 바뀐 쓰기 방식이 이 배율을
차단하지 않았고, 시험용 PDF를 프로그램으로 만들어 썼기 때문에 자동 테스트가
이 상황을 만나지 못했습니다.

고친 뒤 실측(박준원 2001, 15쪽): 글자 7.4~32.6pt, 쪽의 62%를 덮고,
텍스트가 놓인 자리의 잉크 밀도가 쪽 평균의 **2.7~4.8배**입니다.
같은 일이 다시 나면 앱이 스스로 잡아내 화면에 알립니다.

### 릴리스 전 전수 감사에서 나온 넷 (D-069)

모두 **오류를 내지 않고 조용히 틀리던** 것들입니다. 자동 테스트는 초록이었습니다.

- **다권본에서 엉뚱한 권을 읽었습니다.** 卷上·卷下가 함께 있는 문헌에서
  卷下 5쪽을 OCR 하면 **卷上 5쪽 이미지**가 엔진에 넘어갔습니다. 오류 없이
  그럴듯한 결과가 저장되므로 원본과 텍스트의 대응이 조용히 끊어집니다.
  세 곳이 `L1_source/*.pdf`의 첫 파일을 집고 권 식별자를 보지 않았습니다.
- **주석 AI 보조에서 고른 모델이 무시됐습니다.** 화면에서 «Claude로 돌려라»를
  골라도 기본 순서대로 돌았습니다. 값을 라우터 객체에 넣기만 하고 호출에
  넘기지 않고 있었습니다.
- **JSON 저장이 원자적이지 않았습니다.** 저장 도중 정전·강제종료가 나면
  `manifest.json`이 빈 파일로 남아 **그 문헌이 통째로 열리지 않습니다.**
  이제 임시 파일에 다 쓴 뒤 갈아 끼웁니다.
- **파일명·OCR 원문이 이스케이프 없이 화면에 들어갔습니다.**
  `<img src=x onerror=…>.pdf`라는 이름의 파일을 끌어다 놓으면 스크립트가
  실행됐습니다. 12곳을 막았습니다.

### 정리한 것 — 약 1,000줄

전부 «화면 요소가 사라졌는데 코드는 조용히 넘어가던» 같은 패턴입니다.

- 해석 저장소 **「비교 모드」**(약 880줄): 필요한 화면 요소가 하나도 없어
  오래전부터 실행되지 않았습니다.
- **「L5 종류: ○표점 ○현토」 라디오**: 고른 값을 읽는 곳이 비교 모드뿐이라
  **눌러도 아무 일도 일어나지 않았습니다.** 화면에서 뺐습니다 —
  표점·현토는 상단 작업 탭으로 각각 들어갑니다.
- 대조 뷰의 이체자 목록, 하단 패널 토글 등 잔재.

HWP/PDF 가져오기(1,035줄)는 **남겼습니다.** 죽은 코드가 아니라 D-037로
잠가 둔 기능이고, 복원 대상입니다.

### 그 밖에

- **레이아웃 탭에서 블록이 안 보이고 저장을 눌러야 나타나던 것**(D-067).
  L3 좌표계의 배율이 만든 주체마다 달랐습니다. 데이터를 고치지 않고
  그릴 때만 환산하도록 바꿔, 저장 버튼을 누를 일이 없어졌습니다.
- **쪽을 옮기면 텍스트가 뜨기도 안 뜨기도 하던 것**(D-067). 늦게 도착한
  응답이 새 쪽을 덮고 있었습니다. 쪽 로더 3종 모두 가드를 넣었습니다.
- **고쳤는데 화면에 반영되지 않던 것**(D-066). API 응답에 캐시 금지를
  서버가 붙입니다 — 호출부 47곳이 아니라 미들웨어 한 곳에서.
- **화면 여는 데 6.5초 걸리던 것**. `/api/llm/status` 6,572ms → 286ms
  (Ollama 모델 조회 캐시 + OAuth 포트 스캔 결과 캐시).
- **「다음 미확인」 버튼이 동작하지 않던 것**(D-063). 없는 함수를
  `typeof` 가드가 조용히 삼키고 있었습니다.
- **은퇴한 Ollama 클라우드 모델을 계속 부르던 것**(D-062).
  `qwen3-vl:235b-cloud`가 HTTP 410을 돌려주고 있었습니다.
- **추출 패널 아래가 잘리던 것**(D-067). 「쪽별 검수」를 펼치면 목록 끝과
  「검색되는 PDF 만들기」 절이 보이지 않았습니다.
- `--help`가 한국어 Windows 콘솔에서 죽던 것, 쪽 범위 입력에 브라우저가
  옛 값을 되살리던 것.

## 알려진 한계

- 좌표를 주지 않는 엔진(LLM Vision)에서 줄 위치 검출이 실패한 쪽은
  텍스트가 원문 자리가 아닌 곳에 순서대로 놓입니다. 검색은 되지만
  형광이 엉뚱한 데 뜹니다. 산출물 메타데이터에 `page-approximated`로
  기록되고 화면에도 알립니다.
- 앱 안의 PDF 뷰어는 텍스트 레이어를 그리지 않습니다. Ctrl+F는 내보낸
  파일을 외부 뷰어나 서지 관리 도구에서 열 때 동작합니다.
- 프론트엔드 자동 테스트가 없습니다(D-053). 이번 판의 화면 수정은
  jsdom 수동 검증으로만 확인했습니다.
- HWP/PDF 가져오기는 잠겨 있습니다(D-037). 백엔드는 살아 있고
  화면 진입점만 막혀 있습니다 — 복원 대상입니다.
- 문헌 병합은 미구현입니다.
