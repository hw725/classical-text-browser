## 설치

## 키가 없어도 됩니다

이번 판의 판정 모델은 모두 **키가 있을 때만** 쓰입니다. 키를 하나도 넣지 않으면 v1.4.2와 같이 돕니다.
키는 설정 → «판정 모델»에서 넣고 «연결 확인»으로 실제 한 번 불러 봅니다(가입 주소·순서가 칸마다 붙어 있습니다).

| 하는 일 | 키가 있으면 | 없으면 |
|---|---|---|
| 「말로 지시」 자동 스캔의 «무슨 글인가»(이미지 판정) — **GPU 환경에서만**(CPU 서버는 방향만 재고 모델을 부르지 않습니다) | Cloudflare 또는 OpenRouter 키: clef(Cloudflare clef → OpenRouter clef → 기본 비전 모델 순으로 넘어감) | 기본 비전 모델(kimi-k3:cloud, 못 쓰면 «자동») |
| 편성 «판정 모델로 고르기»의 본문 경계 | TypeSafe 키: Jev 직결. TypeSafe 키 없이 OpenRouter 키만: 같은 Jev를 OpenRouter 경유로 | 둘 다 없으면 «판정 모델 키를 찾지 못했습니다»로 시작하는 안내가 설정 → «판정 모델»에서 키를 넣으라고 알립니다(규칙 후보는 그대로) |
| 본문 경계의 폴백(Jev 호출이 실패한 그 호출만) | OpenRouter 키: Perplexity decider | 폴백 없이 그 호출은 실패로 남음 |
| 편성 목차 대조 | TypeSafe 키: Jev 직결. TypeSafe 키 없이 OpenRouter 키만: 같은 Jev를 OpenRouter 경유로 | 둘 다 없으면 위 안내(본문 판정과 함께 멈춤) |
| 애매한 후보 2차 판정 | — 앱은 외부 모델을 부르지 않습니다(아래) | — |

- **OpenRouter 키 하나면 판정 모델이 전부 됩니다** — 이미지 판정의 clef, 본문 경계·목차 대조의 Jev(OpenRouter 경유), 폴백의 decider. (이미지 판정에서 Perplexity Decider를 고르는 것만 Perplexity 키가 따로 필요합니다.) 유료 크레딧이고 이미지 한 쪽 ≈ $0.0004(잰 토큰 수 × 단가로 어림)입니다. 어떤 키도 다른 업체 주소로 나가지 않습니다 — OpenRouter 키는 OpenRouter로, TypeSafe 키는 TypeSafe로만 갑니다. 결과 줄에는 «TypeSafe Jev (OpenRouter 경유)»처럼 누가 답했는지가 나옵니다.
- TypeSafe 키와 OpenRouter 키가 둘 다 있으면 본문 경계·목차 대조의 Jev는 TypeSafe 직결로 갑니다. 직결이 거절되면(TypeSafe 크레딧 소진 402 등) 그 자리에서 같은 Jev를 OpenRouter 경유로 다시 묻고, 그 뒤로는 OpenRouter로만 묻습니다.
- Cloudflare 키(토큰 + 계정 id)가 있으면 이미지 판정은 하루 무료 몫(≈250쪽)부터 쓰고, 다하거나 실패한 쪽부터 OpenRouter로 넘어갑니다. 넘어간 것은 결과 줄에 «넘어감: N쪽부터 OpenRouter clef로(…)»(또는 «기본 비전 모델로»)로 따로 남고, «일부 실패»에는 답을 받지 못한 쪽만 들어갑니다.

## 새로 생긴 것

### 이미지 판정 모델 (D-134·D-135)

자동 스캔의 «무슨 글인가»를 생성형 비전 LLM 대신 **판정 모델**(확률 붙은 답만 돌려주는 모델)로 물을 수 있습니다.
종류 판정은 GPU 환경(바탕화면 아이콘으로 켠 서버)에서만 돌고, CPU 서버의 자동 스캔은 방향만 잽니다.
Cloudflare 또는 OpenRouter 키가 있으면 «종류 판정 모델»의 기본이 clef입니다. Perplexity 키가 있으면 Perplexity Decider도 거기서 고를 수 있습니다.
같은 24쪽으로 잰 값: kimi-k3 종류 21/24·방향 18/24·쪽당 1.99초, OpenRouter clef 종류 20/24·방향 15/24·1.39초.
clef가 빠르지만 정확도는 kimi-k3보다 조금 낮거나 같은 수준입니다(24쪽 표본이라 1장 차이는 우연 범위). 그래도 사용자 결정으로 clef를 기본, kimi-k3를 폴백으로 두었습니다.
clef는 이미지를 300KB로 맞춰 보냅니다(서버가 바이트로 문맥을 어림해 413을 냈습니다).
자동 스캔을 돌리기 전 미리 세기가 clef의 순서(Cloudflare 무료 → OpenRouter 유료 → kimi-k3)와 유료 몫의 최대 비용을 보여 주고,
키가 없으면 설정으로 가는 단추를 띄웁니다. 결과에서 다음 단계가 대신 답한 쪽은 경고가 아니고, 답을 받지 못한 쪽만 경고합니다.
호출 상한에 닿으면 유료 단계로 넘기지 않고 모델 호출을 멈춥니다.

### 편성 본문 경계 판정 — Jev가 주, Perplexity decider는 폴백 (D-136 → D-139)

10월 5일 판은 OpenRouter 경유 Perplexity decider를 본문 경계의 기본으로 두었습니다. 그 모델(v1)이 10월에 OpenRouter에서
내려가(호출하면 «No endpoints found») 새 판(v1.1)으로 다시 쟀습니다. v1.1은 정밀이 조금 높지만 질문마다 글 전체를 다시
세어 책 1권에 Jev의 약 8배($0.19 대 $0.024)가 들어, **Jev를 주로 되돌리고 decider v1.1은 Jev가 실패한 호출만 대신 묻게** 했습니다.
모델마다 확률의 쏠림이 달라 문턱을 따로 둡니다 — Jev가 답한 호출은 0.85 이상을 미리 체크하고 0.5～0.85는 애매한 후보로,
decider가 답한 호출은 0.997 이상을 미리 체크하고 0.69～0.997을 애매한 후보로 둡니다. 애매한 후보는 처음엔 숨어 있고
「애매한 후보 N개 보기」를 누르면 체크하지 않은 채로 보입니다. 목차 대조는 Jev 그대로입니다.
결과 줄의 «누가 답했나»와 비용 합계에 폴백 호출도 들어갑니다.

### NDL古典籍OCR이 만든 신자체를 정자로 (D-138)

NDL古典籍OCR(Full·Lite)은 일본 번각 관례로 학습해 원본의 정자(學·傳·歲)를 신자체(学·伝·歳)로 냅니다. 이 두 엔진의 출력에서만
**하나로 정해지는 글자 293자**를 정자로 되돌립니다(『속음청사』 세 쪽에서 쪽마다 12～29자). 후보가 여럿이거나(弁) 한문에서도
그대로 쓰는 글자(台·余)는 바꾸지 않고 «보류»로 남깁니다. 보류 글자는 문헌별 이체자 승인(為→爲 등)이 있으면 그대로 바꿉니다 —
이미 OCR한 쪽은 `scripts/apply_script_approvals.py`로 미리 본 뒤 적용합니다. 바꾼 자리는 원래 글자와 함께 OCR 결과 기록(L2)에 남습니다(화면에 되돌리는 단추는 아직 없습니다).
다른 엔진의 출력과 교정본(L4)은 건드리지 않습니다. 저장 형식은 바뀌지 않았습니다.

### 애매한 후보 2차 판정 — 내보내기·판정 들이기 (D-137)

편성 탭에 「애매한 후보 내보내기」(후보 100개씩 묶어 복사 — 후보마다 앞 4행·뒤 2행 문맥), 「판정 들이기」, 「저장된 판정 불러오기」, 「2차 아니오 N개 숨기기」가 생겼습니다.
내보낸 글을 쓰시는 채팅 LLM에 붙여 넣고, 받은 답을 「판정 들이기」 칸에 붙여 넣고 「들이기」를 누르면 «아니오»인 후보를 가릴 수 있습니다.
앱이 외부 모델을 직접 부르지 않으므로 키·비용이 들지 않습니다.
실측(정답이 있는 애매한 후보 555행, 진짜 시작 50행): 진짜 시작 48/50을 남기고 사람이 볼 목록이 74행으로 줄었습니다.
이 값은 Claude로 잰 것입니다 — 다른 채팅 LLM은 재지 않았습니다.
판정은 서고 `.escalate_review/<문헌>/<권>.json`에 남고 문헌 git에는 들어가지 않습니다.
내보낸 묶음마다 문헌·권 표지(`esc-…-N`)가 붙어, 다른 권의 답이나 내보낸 글을 그대로 다시 붙인 것은 들이지 않습니다.
같은 후보에 다시 답하면 «다시 판정 N»으로 알리고, 목록을 좁혀 내보내도 그 밖의 들인 판정은 지우지 않습니다(그 행의 글이 바뀌었으면 그 판정은 버립니다).

## 고친 것

### 2026-10-11 전수 검토·릴리스 리뷰로 찾은 것 (B-012～B-078)

저장소 442파일(코드·문서·설정)을 하나씩 읽어 찾은 결함입니다(1차 B-012～B-039, 2차 B-041～B-077, 릴리스 리뷰 B-078). 동작 결함에는 «고치기 전에 실패하는» 시험을 붙였습니다(문서·안내만 고친 것은 시험이 없습니다).

**데이터를 잃을 수 있던 자리**

- **백업 폴더** — 다른 파일이 든 폴더를 백업 폴더로 고르면 그 폴더를 통째로 옮겼다가 두 번째 백업 때 지웠습니다.
  이제 그 안에 하위 폴더를 만들고, 이 앱이 만든 백업만 바꿉니다. «마지막 백업»도 하위 폴더의 백업을 읽습니다
- **`.env` 키 저장** — `.env`를 읽지 못하면(cp949로 저장된 파일 등) 키 하나를 저장할 때 다른 줄이 지워졌습니다.
  이제 cp949로 한 번 더 읽고, 그래도 못 읽으면 쓰지 않습니다
- **휴지통** — 옮기다 파일이 잠기면 완전한 사본을 지우고 원본 조각만 옮기던 것, 되돌리기가 한 번만 해 보고 실패하던 것,
  엔티티·인용·비고만 있는 해석 저장소를 «비었다»며 휴지통에 보내던 것을 고쳤습니다. 잠겨서 못 옮기면 그렇다고 한 번만 알립니다
- **zip으로 깐 PC의 자동 업데이트** — 사용자가 고친 파일을 새 판으로 덮었습니다. 이제 받기 전에 파일 지문을 대조하고,
  지문이 없는 옛 설치본이면 덮기 전에 설정 폴더의 `update-backup/`에 남깁니다. 앱 폴더에 직접 만든 파일을 새 판이
  같은 이름으로 가져오는 경우에도 덮기 전에 거기 남깁니다
- **Ctrl+S** 가 숨은 텍스트 편집기의 옛 글로 확정본을 덮던 것, **비고** 자동 저장이 쪽을 옮긴 뒤 새 쪽 파일을 덮던 것과
  늦게 온 옛 쪽 비고가 지금 쪽에 그려지던 것, **엔티티(Tag·Agent) 편집** 이 metadata를 비우던 것,
  **사전 필드 저장** 이 출전의 section·url을 지우거나 같은 책의 다른 대목을 하나로 합치던 것
- **레이아웃 자동 감지** 가 묻지 않고 기존 블록을 덮던 것(0건이면 지우던 것), 감지 도중 쪽을 옮기면 옛 쪽 블록을 새 쪽에 저장하던 것.
  이제 덮기 전에 묻습니다. 새로 그린 블록의 id가 남은 블록과 겹치던 것도 고쳤습니다

**화면이 동작과 다르던 자리**

- **확장 한자 뒤에서 한 칸 어긋나던 것** — 현토·번역·교정·표점 편집기와 경계 찍기가 글자 위치를 잘못 셌습니다(인용 편집기는 1차에서 고침)
- **PDF를 한 번 못 열면** 다른 문헌의 PDF도 그려지지 않던 것, **쪽 OCR 도중 쪽을 옮기면** 옛 쪽 결과가 지금 쪽에 그려지던 것,
  **LLM 교정 초안** 이 다른 쪽에 그려지던 것
- **실패를 «완료»로 알리던 것** — 쪼개기·단위 삭제의 일부 실패, AI 번역 저장 실패, 교정 리셋·레이아웃 리셋 저장 실패
  (자유 편집의 「교정 리셋」은 교정을 비우지도 못했습니다)
- **스냅샷** 에서 id 없는 엔티티끼리 서로 덮던 것(이제 새 id를 주고 경고), id가 빈 엔티티에서 들이기가 실패하던 것,
  **해석 층 저장** 이 일부 형식에서 실패하고 git 기록을 건너뛰던 것
- **비고** 를 저장하는 도중에 한 다음 저장이 조용히 사라지던 것, **권 전체 OCR** 방향이 세로로 고정돼 있던 것(이제 문헌 프로필을 따름),
  **폴더 배치 OCR** 이 같은 경로에 새로 놓인 다른 스캔에 옛 OCR을 이어 쓰던 것, 교정본이 빈 쪽에서 경계 찍기 미리보기가 멈추던 것
- 해석 저장소를 고르지 않았을 때 없는 저장소(«default»)로 요청하던 것(주석·인용) — 이제 그렇다고 알립니다
- 인용 «원문 변경» 경고가 영영 보이지 않던 것, 일괄 교정 칸에 확장 한자를 넣을 수 없던 것, 위 바의 쪽 번호가 ◀▶에서 바뀌지 않던 것,
  서지 수동 편집에서 칸을 비워도 지워지지 않던 것, 라벨에 `“`가 그대로 보이던 것, 리셋 단추가 권 전체인데 «이 쪽»이라 적혀 있던 것
- **화면 라이브러리(PDF.js 등)를 앱이 직접 싣습니다** (D-140) — 전에는 인터넷(CDN)에서 받아, 처음 켤 때 인터넷이 없으면 PDF가 뜨지 않을 수 있었습니다

**그 밖**
