# v1.4.3 — 판정 모델: 이미지는 clef, 본문 경계는 decider, 애매한 후보는 붙여 넣기로

날짜: 2026-10-05 · 범위: v1.4.2 이후 · **되돌릴 수 없는 변화 없음**(저장 형식은 더하기만 했다 — 서고의 `.escalate_review/` 하나, 문헌 git 밖)

## 설치

- Windows — 아래 **Assets** 의 `CTB-Setup.exe` → 두 번 누르기 → 폴더·엔진 고르기 → 「설치」 → 「지금 실행」
- 이미 깔린 PC — `start_server.bat`을 켜면 저절로 새 판을 받습니다
- macOS·Linux — zip을 풀고 `./install.sh`

## 키가 없어도 됩니다

이번 판의 판정 모델은 모두 **키가 있을 때만** 쓰입니다. 키를 하나도 넣지 않으면 v1.4.2와 같이 돕니다.
키는 설정 → «판정 모델»에서 넣고 «연결 확인»으로 실제 한 번 불러 봅니다(가입 주소·순서가 칸마다 붙어 있습니다).

| 하는 일 | 키가 있으면 | 없으면 |
|---|---|---|
| 「말로 지시」 자동 스캔의 «무슨 글인가»(이미지 판정) — **GPU 환경에서만**(CPU 서버는 방향만 재고 모델을 부르지 않습니다) | Cloudflare 또는 OpenRouter 키: clef(Cloudflare clef → OpenRouter clef → 기본 비전 모델 순으로 넘어감) | 기본 비전 모델(kimi-k3:cloud, 못 쓰면 «자동») |
| 편성 «판정 모델로 고르기»의 본문 경계 | OpenRouter 키: Perplexity decider. TypeSafe 키만: Jev | 둘 다 없으면 «판정 모델 키를 찾지 못했습니다»로 시작하는 안내가 설정 → «판정 모델»에서 키를 넣으라고 알립니다(규칙 후보는 그대로) |
| 본문 경계의 폴백(decider 호출이 실패한 그 호출만) | TypeSafe 키 또는 OpenRouter 키로 Jev | 폴백 없이 그 호출은 실패로 남음 |
| 편성 목차 대조 | TypeSafe 키: Jev 직결. TypeSafe 키 없이 OpenRouter 키만: 같은 Jev를 OpenRouter 경유로 | 둘 다 없으면 위 안내(본문 판정과 함께 멈춤) |
| 애매한 후보 2차 판정 | — 앱은 외부 모델을 부르지 않습니다(아래) | — |

- **OpenRouter 키 하나면 판정 모델이 전부 됩니다** — 이미지 판정의 clef, 본문 경계의 decider, 목차 대조와 폴백의 Jev(OpenRouter 경유). 유료 크레딧이고 이미지 한 쪽 ≈ $0.0004(실측)입니다. 어떤 키도 다른 업체 주소로 나가지 않습니다 — OpenRouter 키는 OpenRouter로, TypeSafe 키는 TypeSafe로만 갑니다. 결과 줄에는 «TypeSafe Jev (OpenRouter 경유)»처럼 누가 답했는지가 나옵니다.
- TypeSafe 키와 OpenRouter 키가 둘 다 있으면 목차 대조·폴백의 Jev는 TypeSafe 직결로 갑니다.
- Cloudflare 키(토큰 + 계정 id)가 있으면 이미지 판정은 하루 무료 몫(≈250쪽)부터 쓰고, 다하거나 실패한 쪽부터 OpenRouter로 넘어갑니다. 넘어간 쪽은 결과 줄의 «일부 실패: …» 뒤에 «이 쪽부터 OpenRouter clef로»(또는 «기본 비전 모델로»)로 남습니다.

## 새로 생긴 것

### 이미지 판정 모델 (D-134·D-135)

자동 스캔의 «무슨 글인가»를 생성형 비전 LLM 대신 **판정 모델**(확률 붙은 답만 돌려주는 모델)로 물을 수 있습니다.
종류 판정은 GPU 환경(바탕화면 아이콘으로 켠 서버)에서만 돌고, CPU 서버의 자동 스캔은 방향만 잽니다.
Cloudflare 또는 OpenRouter 키가 있으면 «종류 판정 모델»의 기본이 clef이고, Perplexity Decider도 거기서 고를 수 있습니다.
같은 24쪽으로 잰 값: kimi-k3 종류 21/24·방향 18/24·쪽당 1.99초, OpenRouter clef 종류 20/24·방향 15/24·1.39초.
clef가 빠르지만 정확도는 kimi-k3보다 조금 낮거나 같은 수준입니다(24쪽 표본이라 1장 차이는 우연 범위). 그래도 사용자 결정으로 clef를 기본, kimi-k3를 폴백으로 두었습니다.
clef는 이미지를 300KB로 맞춰 보냅니다(서버가 바이트로 문맥을 어림해 413을 냈습니다).
자동 스캔을 돌리기 전 미리 세기가 clef의 순서(Cloudflare 무료 → OpenRouter 유료 → kimi-k3)와 유료 몫의 최대 비용을 보여 주고,
키가 없으면 설정으로 가는 단추를 띄웁니다. 결과에서 다음 단계가 대신 답한 쪽은 경고가 아니고, 답을 받지 못한 쪽만 경고합니다.
호출 상한에 닿으면 유료 단계로 넘기지 않고 모델 호출을 멈춥니다.

### 편성 본문 경계 판정의 기본을 decider로 (D-136)

같은 정답으로 견준 F1에서 OpenRouter 경유 Perplexity decider가 Jev보다 높아(천진담초 0.846 대 0.818, 운양집 1책 0.814 대 0.743) 기본으로 삼았습니다.
decider는 확률이 위로 몰려 문턱을 따로 둡니다 — 확실한 것(0.95 이상)은 미리 체크, 애매한 것(0.35～0.95)은 체크를 푼 후보로 보입니다.
decider 호출이 실패하면 그 호출만 Jev에 다시 묻습니다(Jev가 답한 호출에는 Jev 문턱 0.85/0.5). 목차 대조는 Jev 그대로입니다 — TypeSafe 키가 없으면 OpenRouter 경유로 부릅니다.

### 애매한 후보 2차 판정 — 내보내기·판정 들이기 (D-137)

편성 탭에 「애매한 후보 내보내기」(후보 100개씩 묶어 복사 — 후보마다 앞 4행·뒤 2행 문맥), 「판정 들이기」, 「저장된 판정 불러오기」, 「2차 아니오 숨기기」가 생겼습니다.
내보낸 글을 쓰시는 채팅 LLM에 붙여 넣고, 받은 답을 「판정 들이기」에 붙여 넣으면 «아니오»인 후보를 가릴 수 있습니다.
앱이 외부 모델을 직접 부르지 않으므로 키·비용이 들지 않습니다.
실측(정답이 있는 애매한 후보 555행, 진짜 시작 50행): 진짜 시작 48/50을 남기고 사람이 볼 목록이 74행으로 줄었습니다.
이 값은 Claude로 잰 것입니다 — 다른 채팅 LLM은 재지 않았습니다.
판정은 서고 `.escalate_review/<문헌>/<권>.json`에 남고 문헌 git에는 들어가지 않습니다.
내보낸 묶음마다 문헌·권 표지(`esc-…-N`)가 붙어, 다른 권의 답이나 내보낸 글을 그대로 다시 붙인 것은 들이지 않습니다.
같은 후보에 다시 답하면 «다시 판정 N»으로 알리고, 목록을 좁혀 내보내도 그 밖의 들인 판정은 지우지 않습니다.

## 고친 것

- **자유 교정이 되돌아간 것처럼 보이던 것** (D-133) — 글자 교정 보기가 넣기·지우기·여러 글자 바꾸기를 교정본대로 그립니다.
  저장 뒤 교정 목록을 다시 읽어, 옛 목록으로 다시 저장하면 고친 것이 지워지던 길을 막았습니다
- **확정본을 다시 써도 사람 교정이 남습니다** (D-133) — OCR 확정본 채우기·권 전체 OCR·텍스트레이어 가져오기·HWP 가져오기·
  강독 결과 들이기·LLM 교정 적용·일괄 교정 등 확정본을 다시 쓰는 길이 모두 사람 교정을 새 글 위로 옮겨 붙입니다(겹치면 사람 판).
  다시 OCR해 글이 크게 바뀌어 옛 글과 맞춰 볼 수 없으면 교정을 억지로 붙이거나 옛 글을 되살리지 않고, 지우지도 않고
  교정 목록의 «기록»으로 옮깁니다. 옮겨 붙였는지·기록으로 옮겼는지는 화면 알림으로 알려 드립니다(「N쪽: 새 글이 옛 글과
  많이 달라 사람 교정 N건을 새 글에 옮기지 못했습니다 — 지우지 않고 교정 목록에 «기록»으로 남겼습니다.」)
- **교정·편집을 잃지 않게 화면이 막고 알립니다** (D-133)
  - 저장하지 않은 자유 편집이 있으면 「글자 교정」으로 넘어가지 않습니다(«저장하지 않은 자유 편집이 있습니다. 먼저 저장(Ctrl+S)한 뒤 글자 교정으로 넘어가세요.»)
  - 저장하지 않은 편집이 있으면 쪽을 옮길 때 묻고(«저장하지 않은 수정이 있습니다: … 저장하지 않고 이동하시겠습니까?»), 창을 닫을 때는 브라우저가 나갈지 묻는 확인 창을 띄웁니다
  - 열람 탭은 교정이 있는 쪽에서 «교정 전 글 (교정 N건은 교정 탭에)»이라고 밝힙니다
  - 텍스트레이어 PDF가 교정 전 확정본이 아니라 교정본을 싣습니다
  - «작업 계획대로»가 켜져 있으면 「권 전체 OCR」의 «돌아간 쪽은 세워서»가 잠깁니다 — 회전은 「말로 지시」 ③에서 적용한 계획대로 씁니다
- **편성 «바뀐 것»과 「적용」의 숫자가 어긋나던 것** — 저장된 경계가 없을 때 «바뀐 것»은 확신 후보만 세고 「적용」은 체크한 후보 전부를 저장했습니다.
  이제 둘이 같은 계산을 씁니다
- **설치 중 Ollama가 꺼져 있으면 멈추던 것** (D-114 후속) — Ollama가 깔려 있으나 꺼진 PC에서 설치가 «[5-1] Ollama 기본 비전 모델 확인»에서 끝나지 않았습니다(v1.4.2에도 있던 결함). 이제 몇 초 안에 «Ollama가 꺼져 있습니다 — 나중에 켜면 됩니다»로 넘어갑니다
- **키·비전 모델이 없을 때 미리 보기가 그렇다고 말합니다** (D-136·D-135 후속) — 편성 «판정 모델로 고르기»는 누르기 전에 «키 없음»을, 자동 스캔은 «쓸 수 있는 비전 모델이 없습니다»와 사슬 끝(기본 비전 모델)이 «지금 닿지 않음»을 알립니다
