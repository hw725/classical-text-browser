# v1.2.2 릴리스 노트

날짜: 2026-08-20
범위: v1.2.1 이후 (D-077 ~ D-078)

## 한 줄 요약

**GPU 가속을 별도 가상환경(`.venv-gpu`)으로 분리**했습니다. `start_server.bat`이
실행할 때마다 GPU를 감지해 자동으로 골라 쓰므로, 사용자가 고르거나 복구할 것이
없습니다. v1.2.1의 「GPU 수동 전환 + `uv sync` 후 재설치」 절차는 폐기입니다 —
sync가 돌 때마다 GPU 스택이 되돌아가던 함정을 문서 대신 구조로 막았습니다(D-078).

되돌릴 수 없는 변화: **없음.** 서고·문헌·해석 저장소·서버 코드 무변경.
CPU 사용자는 달라지는 것이 없습니다.

## 바뀐 것

| 환경 | 내용 | 관리 |
|---|---|---|
| `.venv` | CPU 정본 — 락파일과 항상 일치 | `uv sync`·`uv run` 자유 |
| `.venv-gpu` | GPU 스택(torch + NDL古典籍OCR Full + paddlepaddle-gpu) | user-guide §7-A.6-2의 재생성 명령으로만. `uv sync`·`uv run` 금지 |

- `start_server.bat`: 시작 시 GPU 감지 → `.venv-gpu` 있으면 그 환경으로,
  아니면 기존대로 `.venv`. 선택 결과를 `[Env]` 줄로 표시.
- torch 인덱스 플랫폼 분기: **Windows cu124 · Linux cu126.** Linux에서
  torch와 paddlepaddle-gpu의 nvidia-* 핀이 일치하게 되어, v1.2.1의
  「한 환경에서 의존성 해석 자체가 실패한다」 한계가 해소됐습니다.
  (Windows는 cu126 통일이 불가함을 실측으로 확인하고 cu124를 유지 — 상세 D-078)
- 문서: user-guide §7-A.6-2 전면 개정(두-환경 절차), README·CLAUDE.md 동기화,
  D-077·D-078 기록.

## 업그레이드 안내

- **GPU 사용자**: user-guide §7-A.6-2 절차로 `.venv-gpu`를 한 번 만들면
  끝입니다. 이후 sync·업데이트가 `.venv`를 어떻게 바꾸든 GPU 환경은
  영향받지 않습니다. 예전 수동 교체 상태였다면 `uv sync` 한 번으로
  `.venv`를 되돌린 뒤 위 절차를 따르면 됩니다.
- **CPU 사용자**: 할 일 없음.

## 확인한 범위

- pytest **668 passed** · ruff · JS 문법 검사 통과
- GPU 경로: 감지 → `.venv-gpu` 서버 기동 → HTTP 200. torch·paddle 모두
  CUDA 실연산 확인
- CPU 경로: 미감지 분기 → `.venv` 서버 기동 → HTTP 200
- 실사용 부하: `.venv-gpu`에서 한문 필사본 수천 쪽 OCR 배치 가동 중 검증

## 알려진 한계

- `.venv-gpu` 안에서 torch 계열(NDL Full)과 paddle 계열(PaddleOCR GPU)을
  **한 파이썬 프로세스에 동시 로드할 수 없습니다**(cudnn 충돌). 실사용
  경로(OCR 실행당 엔진 하나)에서는 걸리지 않습니다.
- GPU 없는 실물 PC 실기동은 못 했고, CPU 분기는 시뮬레이션으로
  검증했습니다. 그 분기의 코드는 v1.2.1과 동일합니다.
- `.venv-gpu` 생성에는 paddlepaddle-gpu 설치라는 수동 한 단계가 남습니다
  (GPU 스택을 기본 의존성으로 만들지 않는 방침 유지 — D-076).
- v1.2.1의 알려진 한계 중 「Linux 해석 충돌」은 해소, 나머지는 그대로입니다.
