# v1.2.2 — GPU는 별도 환경으로

되돌릴 수 없는 변화: **없음.** 기존 서고·문헌·해석 저장소에 영향 없음.
CPU 사용자는 달라지는 것이 없고, 예전 GPU 수동 전환 상태도 그대로 동작한다
(다만 이제 지원 절차가 아니다 — 아래 참조).

## 요약

GPU 가속의 설치 방식을 바꿨습니다. 예전에는 하나의 가상환경에서 CPU판
paddle을 GPU판으로 **수동 교체**하고, `uv sync`가 돌 때마다 되돌아가는 함정을
문서로만 막고 있었습니다(v1.2.1 §7-A.6-2 「알아 둘 것」 2·3번). 이번부터
환경이 두 개입니다 — `.venv`(CPU 정본, 락파일과 항상 일치)와 `.venv-gpu`(GPU
스택). `start_server.bat`이 실행할 때마다 GPU를 감지해 자동으로 골라 주므로,
**사용자가 고르거나 복구할 것이 없습니다.**

## 바뀐 것

- **`start_server.bat`**: 시작 시 `nvidia-smi`로 GPU 감지 → `.venv-gpu`가 있으면
  그 환경의 python을 직접 실행, 없거나 GPU가 없으면 기존처럼 `.venv`(CPU).
  선택 결과를 `[Env]` 줄로 표시.
- **`.venv-gpu` 규약 신설**: 락파일 기반(`--extra ndlkotenocr --extra
  classical-gpu`) + paddlepaddle-gpu 오버레이. 만들기·재생성은
  user-guide §7-A.6-2 네 줄이 전부.
- **user-guide §7-A.6-2 전면 개정**: 수동 교체 절차 폐기. 「sync 하면
  되돌아가니 다시 설치하라」는 안내 삭제. uv 함정 2건 실측 기록
  (`uv pip`의 대상 환경 무시, `uv run`의 락 복원).
- **README 엔진 표**: NDL Full 설치 안내를 `.venv-gpu` 절차로 교체.
- **CLAUDE.md**: 「GPU 스택은 .venv에 설치하지 않는다」 규칙 추가.
- `.gitignore`: `.venv-gpu/` 추가.
- 설계 기록: D-077(파일 계약과 얇은 소비자), D-078(두-환경 이원화 — D-076의
  설치 층 미해결분 마감).

## 왜 바꿨나

「수동 상태 + 그것을 지우는 도구 + 경고 문서」 구조는 2026-08-20 하루에만
세 번 무너졌습니다(sync가 paddle-gpu 삭제, run이 상향 패키지 2종 원복, 같은
`paddle` 이름공간 공유로 인한 패키지 디렉터리 파손). 문서가 막던 것을 구조가
막게 했습니다. 상세: D-078.

## 검증 (2026-08-20 실측)

- `.venv-gpu`: torch 2.6.0+cu124 CUDA `True` · paddlepaddle-gpu 3.3.1 CUDA
  `True` · NDL古典籍OCR Full/Lite·NDLOCR·PaddleOCR 등록 확인
- GPU 경로: `start_server.bat` → `[Env] NVIDIA GPU detected - using .venv-gpu`
  → Uvicorn 기동 → HTTP 200
- CPU 경로: GPU 미감지 분기 확인(`[Env] no GPU detected`), `.venv`(락 정본)
  서버 기동 → HTTP 200
- 지속 부하: NDL Full·Lite 배치가 `.venv-gpu`에서 수천 쪽 규모 OCR 처리 중
  가동 검증
- pytest·ruff·node --check: 릴리스 커밋 전 통과 확인

## 업그레이드 안내

- GPU 사용자: user-guide §7-A.6-2 절차로 `.venv-gpu`를 한 번 만들면 끝.
  이후 sync·업데이트가 `.venv`를 어떻게 바꾸든 GPU 환경은 영향받지 않는다.
  예전 수동 교체 상태로 쓰고 있었다면 `uv sync` 한 번으로 `.venv`를 CPU
  정본으로 되돌린 뒤 위 절차를 따르면 된다.
- CPU 사용자: 달라지는 것 없음.
