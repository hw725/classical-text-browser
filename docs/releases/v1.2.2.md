# v1.2.2 릴리스 노트

날짜: 2026-08-20
범위: v1.2.1 이후 (D-077 ~ D-078)

## 한 줄 요약

**GPU 가속을 별도 가상환경(`.venv-gpu`)으로 분리**하고, `start_server.bat`이
실행할 때마다 GPU를 감지해 자동으로 골라 쓰게 했습니다. v1.2.1의 「GPU 수동
전환 + sync 하면 되돌아가니 다시 설치하라」 절차는 폐기입니다.

되돌릴 수 없는 변화: **없음.** 서고·문헌·해석 저장소·서버 코드 전부 무변경.
CPU 사용자는 실행 경로가 바이트 단위로 이전과 같습니다.

## 왜 이 판이 나왔나

v1.2.1은 GPU 전환을 「단일 환경에서 CPU판을 GPU판으로 교체」로 안내하면서,
바꾼 뒤 알아야 할 함정 셋을 문서에 적어 두었습니다. 그 구조 —
**수동 상태 + 그것을 지우는 도구 + 경고 문서** — 가 2026-08-20 하루에
세 번 무너졌습니다.

1. `uv sync --extra ndlkotenocr` 한 번에 수동 설치된 paddlepaddle-gpu가
   삭제됐습니다. 문서에 경고된 그대로였지만, 경고는 읽는 사람에게만 작동합니다.
2. `uv run`이 실행 전 락파일 기준으로 환경을 되돌려, 수동으로 올린
   huggingface-hub·safetensors를 두 차례 원복시켰습니다.
3. paddlepaddle-gpu 제거가 같은 `paddle` 이름공간을 공유하는 CPU판의 패키지
   디렉터리까지 파손시켰습니다 — pip 메타데이터에는 있는데 import는 실패하는
   상태(v1.2.0에서 opencv contrib/headless로 겪은 것과 같은 병).

경고 문서가 막던 것을 구조가 막게 바꿨습니다. 상세: D-078.

## 바뀐 것

### 환경 이원화 (D-078)

| 환경 | 내용 | 관리 |
|---|---|---|
| `.venv` | CPU 정본 — 락파일과 항상 일치 | `uv sync`·`uv run` 자유 |
| `.venv-gpu` | GPU 스택: torch cu124 + NDL古典籍OCR Full + paddlepaddle-gpu | 재생성 명령으로만. **`uv sync`·`uv run` 금지, python 직접 호출** |

`.venv-gpu`는 락파일 기반(`--extra ndlkotenocr --extra classical-gpu`)에
paddlepaddle-gpu 하나만 오버레이합니다. 만들기는 user-guide §7-A.6-2의 네 줄.

### 실행 시 자동 선택

`start_server.bat`이 시작할 때 `nvidia-smi`로 GPU를 감지합니다.

```
[Env] NVIDIA GPU detected - using .venv-gpu
```

GPU가 없거나 `.venv-gpu`가 없으면 기존 그대로 `.venv`(CPU)로 갑니다. GPU
환경은 `uv run`을 거치지 않고 python을 직접 호출합니다 — `uv run`은 실행 전
동기화로 GPU 스택을 지우기 때문이며, 이것이 이 판의 핵심 설계입니다.

## 확인한 범위

- `uv run python -m pytest` — **668 passed** (v1.2.1의 667+1, 14분 3초)
- `ruff check src/ tests/` 통과, JS 문법 검사 통과
- **GPU 경로 실기동**: `start_server.bat` → `[Env] NVIDIA GPU detected` →
  Uvicorn 기동 → HTTP 200. `.venv-gpu`에서 torch 2.6.0+cu124 CUDA `True`,
  paddlepaddle-gpu 3.3.1 CUDA `True`, NDL Full·Lite·NDLOCR·PaddleOCR 등록 확인
- **CPU 경로 실기동**: GPU 미감지 분기(`[Env] no GPU detected`) 확인 후
  `.venv`(락 정본)로 서버 기동 → HTTP 200
- **지속 부하**: 이 판의 `.venv-gpu`에서 NDL Full·Lite 배치가 한문 필사본
  수천 쪽 규모 OCR을 처리하며 가동 검증(외부 프로젝트 실사용)
- 검증 중 잡은 것 하나: 감지 명령을 `call nvidia-smi`로 적었습니다 —
  PATH에 같은 이름의 .bat 셔닝이 있어도 배치 제어가 넘어가지 않습니다

## 알려진 한계

- **GPU 없는 실물 PC에서의 실기동은 하지 못했습니다.** CPU 분기는 이
  PC에서 감지 실패를 시뮬레이션해 검증했습니다. 다만 그 분기가 타는 코드는
  v1.2.1과 동일하고, 감지가 어떤 이유로든 실패하면 방향은 CPU 폴백(안전한
  쪽)입니다.
- `nvidia-smi`가 PATH에 없는 GPU 머신(드라이버 설치 이상)은 CPU로
  폴백합니다 — GPU를 쓰려면 드라이버부터 정상화해야 합니다.
- `.venv-gpu` 생성에는 paddlepaddle-gpu 오버레이라는 **수동 한 단계**가
  여전히 남습니다(paddle GPU 휠은 전용 인덱스에만 있고 락에 넣지 않는
  방침 — D-076 결정 4 유지). 자동화하려면 설치 스크립트 확장이 필요합니다.
- 두 환경 몫의 디스크를 씁니다. uv 하드링크로 공유되는 부분이 있어 겉보기
  합계보다는 적게 듭니다.
- torch cu124와 paddle cu126의 CUDA 버전 불일치는 Windows에서는 각 휠이
  자체 DLL을 품어 공존했습니다(실측). Linux에서는 v1.2.1에 적은 대로
  해석 충돌이 그대로 있습니다.
- v1.2.1의 알려진 한계는 그대로입니다.
