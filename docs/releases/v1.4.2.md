# v1.4.2 — 말로 작업 지시: 복잡한 스캔본 한 권을 스캔·말 → 계획 → OCR → 텍스트·노트로

날짜: 2026-10-02 · 범위: v1.4.1 이후(편성 Jev 1차 거름망 포함) · **되돌릴 수 없는 변화 없음**(저장 형식은 더하기만 했다 — 문헌 폴더의 `read_plan/{권}.json` 하나)

## 설치

- Windows — 아래 **Assets** 의 `CTB-Setup.exe` → 두 번 누르기 → 폴더·엔진 고르기 → 「설치」 → 「지금 실행」
- 이미 깔린 PC — `start_server.bat`을 켜면 저절로 새 판을 받습니다
- macOS·Linux — zip을 풀고 `./install.sh`

## 새로 생긴 것

### 뷰어 도구 모음의 「말로 지시」

돌아간 2쪽 펼침, 선 활자, 초서 필사본, 가로쓰기, 한글 번역이 섞인 사진본, 표가 한 권에 뒤섞여 있어도
쪽마다 회전·엔진을 고르지 않아도 됩니다. 코드가 잴 수 있는 것은 **스캔**이 재고, 이 책에 대해 아는 것은
**말로** 적으면 한 창에서 세 단계로 끝납니다.

1. **자동 스캔** — 쪽을 훑어 회전과 글의 종류(→ OCR 엔진)를 잽니다. 잰 값은 계획 표에 **바로** 들어갑니다
   (글로 풀어 LLM이 다시 옮기게 하지 않습니다). 종류 판정은 GPU 환경에서만이고, CPU에서는 방향만(옆으로 누운 쪽만) 잽니다.
   예전의 「판독 계획」 단추가 이 자리로 들어왔습니다 — 두 단추가 같은 계획을 서로 덮어썼습니다.
2. **말로 덧붙이기** — 「장은 5쪽 壹. …, 80~97쪽은 초서 필사본, 교재 면은 PDF 쪽 − 4」. LLM이 지금 계획
   위에서 고칠 데만 고칩니다. **옮기지 못한 말은 그대로 보여 주고**, 말이 스캔과 다른 회전을 적은 쪽은
   «말과 스캔이 다른 쪽»으로 짚습니다.
3. **계획 확인·적용** — 표의 「보기」(구간 첫 쪽을 그 회전으로 그림)·「반대로」(+180°)로 확인하고 「적용」.
   회전·판독 지침·장 목록이 저장되고, 「권 전체 OCR」이 구간마다 계획의 엔진·쓰기 방향으로 돕니다
   (한 권 안에 세로·가로가 섞여도 됩니다).

### 교정 탭 «들이기·내보내기» — 텍스트 내려받기와 LLM 결과 들이기

OCR·교정이 끝난 뒤의 일은 교정 탭의 새 서브탭에서 합니다.

- **텍스트로 내려받기** — 확정본에서 **PDF 판면 때문에 생긴 줄바꿈을 지우고**(쪽마다 되풀이되는 머리글·쪽
  번호도 뺍니다. 글자는 고치지 않습니다) 문단으로 이어 마크다운·미디어위키 한 파일(또는 장별 zip)로 줍니다. 논문 한 편을 OCR해 텍스트 레이어 PDF를 만든 뒤 마크다운이
  필요할 때 쓰세요. «논문» 모드 추출 패널에도 «3. 텍스트로 내려받기»가 있습니다.
- **LLM 결과 들이기** — LLM(예: Claude Code 세션)이 쪽 이미지를 보고 만든 교정·번역·어휘 JSON을 넣습니다.
- **노트 틀** — 원하는 노트 예시를 붙여 넣어 틀을 만들고 그 틀로 내려받습니다. 모양만 LLM이 읽고,
  원문·번역·어휘는 서고에서 채웁니다.

### LLM 결과는 새 저장 형식 없이 기존 층으로

LLM이 돌려준 결과는 이미 있는 자리에 나눠 담깁니다 — 교정은 확정본(L4), 장·문서 항목은 편성 경계,
구획별 국역은 번역(L6), 어휘·문법은 사전형 주석(L7), 해제·요점·검토 메모는 주석의 비고. **사람이 이미 고친
확정본·번역·주석은 덮지 않고**(교정 탭·편집기에서 고친 확정본, 번역·주석 탭에서 고친 국역·어휘, 사람이 세운
경계), 같은 결과를 다시 들이면 앞서 들인 것만 바뀝니다. 노트는 저장하지 않고
내려받을 때마다 이 층들에서 다시 조립하므로, 교정·번역·주석 탭에서 고친 것이 그대로 들어갑니다.

### 장별 내보내기

- 쪽 표시에 **PDF 쪽과 책의 쪽 번호를 함께** — «PDF p.46 · 교재 42면». 쪽 번호 체계는 작업 계획의
  «쪽 이름표»가 정합니다(예: 교재 면 = PDF 쪽 − 4, 어긋나는 쪽은 따로)
- 손글씨 쪽 번호·접힌 자리의 선을 글자로 읽은 잡음 줄, 쪽마다 되풀이되는 머리글은 뺍니다
- 줄은 문단으로 잇습니다(끌 수 있음) — 세로쓰기는 그대로 붙이고, 가로쓰기는 빈칸 하나(한자·가나끼리는 붙임,
  영어 «con-»은 하이픈을 떼고 붙임). 쪽을 넘는 문단은 하나로 이으면서 이음매에 «[PDF p.N]»을 넣습니다
- **가로쓰기 한글은 줄이 어절 한가운데서 꺾였는지 같은 문헌 안에서 근거를 찾아 가립니다** — 옛 국한문 논문은
  «그대|로»·«있|다»처럼 줄이 어절 한가운데서 꺾입니다. 사전 없이 판정하므로 틀리는 자리가 남습니다
  (13쪽 논문에서 줄 경계 310곳 가운데 본문 열댓 곳, 눈대중)
- OCR 결과에 줄 좌표가 있으면 문단 끝·들여쓰기를 좌표로 가립니다

### 번역 탭 AI 번역이 용어 풀이를 따른다

그 단위에 사전형 주석이 있으면, 원문에 나오는 표제어의 풀이를 함께 보냅니다 — 검토한 풀이는 «확정 용어 풀이»로
우선하게, 검토 전 초안은 참고로만.
번역 규칙에 «용어 풀이 우선 · 평이한 현대어 · 없는 뜻을 더하지 않음 · 이두는 한국어 조사로»를 넣었습니다.

### 명령줄 `ctb read`

많은 쪽을 밤새 돌리거나 에이전트가 부를 때 — `ctb read 교재.pdf --doc-id lecture --said "…"`(계획 초안) →
`--plan 계획.json --execute`(OCR) → `--note 결과.json`(들이기) → `--export md,wiki`(내보내기).

### 편성 — 판정 모델(Jev)의 애매한 후보를 따로

편성 탭 「더 묻기…」의 판정 모델(TypeSafe Jev) 답을 문턱 하나로 자르지 않고 셋으로 나눕니다. 확실한 것
(본문 0.85 이상)은 미리 체크, 애매한 것(0.5~0.85)은 **체크를 풀어 둔 후보**로 「애매한 후보 N개 보기」에서
«애매 0.62» 배지와 함께 보이고, 나머지는 후보에서 뺍니다. 목차 대조에서 자리를 못 찾은 제목은 목록으로
보여 줍니다. 애매한 후보는 규칙 후보를 채택으로 끌어올리지 않습니다(D-129 적용 기록).

## 고친 것

- 열람·추출 모드에서 쪽을 열기만 해도 확정본(L4)을 채우던 것 — 이제 교정 탭에서만 채웁니다.
- 화면을 열기만 해도 경계 파일이 «수정됨»이 되던 것(L4 커밋 값만 바뀐 재대조를 쓰지 않음).
- 편성 탭 「단위 손보기」의 단위 번호가 내용 트리와 한 칸 어긋나던 것.
- 좁은 창에서 PDF 도구 줄의 회전 표시가 옆 단추 위에 겹치던 것(넘치면 두 줄로).
- 번역 탭이 들인 LLM 결과의 번역을 «미번역»으로 보이던 것.
- JSON 파일을 저장하던 열여섯 자리가 도중에 죽으면 빈 파일을 남길 수 있던 것 — 모두 «다 쓴 뒤 바꿔 넣기»로
  저장합니다. LLM에게 보내는 쪽 이미지가 저장된 회전(쪽 범위 회전 포함)을 따르지 않던 자리도 고쳤습니다.

## 바뀐 것

- 「판독 계획」 단추와 창을 없앴습니다 — 「말로 지시」의 ① 자동 스캔이 같은 일을 합니다(위).
- OCR 패널의 «판독 계획대로»가 «작업 계획대로»로 바뀌었습니다. 걸린 계획은 그 화면에만 있습니다 — 화면을
  새로 열었으면 「말로 지시」에서 「적용」을 한 번 더 누르세요.
- 내려받는 노트 파일 이름이 `강독_…`에서 `노트_…`로 바뀌었습니다.

## 없앤 것

- 화면이 부르지 않던 LLM 레이아웃 분석 API 셋 — `/api/llm/analyze-layout`·`/api/llm/compare-layout`·
  `/api/llm/drafts/{id}/review`. 초안이 메모리에만 있어 서버를 다시 켜면 사라졌고, 승인해도 레이아웃(L3)에
  쓰지 않았습니다. 화면의 레이아웃 자동감지(NDL 계열)는 그대로입니다

## 알아 둘 것

- LLM 비전 구간은 모델 한도의 영향을 받습니다(Ollama 클라우드는 월 한도). 실패한 쪽은 이유와 함께 알려 주고,
  한도가 풀린 뒤 「권 전체 OCR」을 다시 누르면 실패한 쪽만 돕니다
- 흐린 사진본·손글씨·표가 많은 책에서는 자동 방향 판정이 «모름»을 많이 냅니다 — 방향은 말로 주세요
