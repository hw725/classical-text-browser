릴리스에 묶이지 않은 개선 요청을 기록한다. 착수 시 DECISIONS에 설계 결정을 남기고

## B-001 세로쓰기 대조 교정 뷰 (2026-08-21, 운양 프로젝트 사용 경험에서)

원문 이미지와 텍스트를 나란히 놓고 **세로쓰기(vertical-rl) + 행별 하이라이팅**
상태에서 행 텍스트를 교체(교정)하고 이력이 남는 뷰. 현재 ctb의 교정 UI는 가로쓰기
중심이라, 고서(세로쓰기) 대조 교감 작업에는 외부 뷰어(운양 `viewer/index.html` +
`17_viewer_server.py`)를 따로 만들어 썼다.

- 요구: ① 세로쓰기 텍스트 패널 ② 이미지 bbox ↔ 행 클릭 동기 하이라이팅
  ③ 행 단위 텍스트 교체 저장 ④ 수정 이력 누적(ctb는 git 이력이 이미 있으므로 연결만)
- 참고 구현: 운양 뷰어의 층위 규약(text < text_corrected < text_human,
  append-only human_edits.jsonl)과 PDF.js 오버레이 방식
- 관련 우려(같은 대화에서): 속음청사급(18권 3,018쪽) 대규모 문헌을 ctb가 감당하는지
  1권 파일럿 실측 필요 — 적재·편집·git 커밋 응답속도

## B-002 PDF에서 위치를 찍어 경계 넣기 (2026-09-03, 사용자 제안)

지금 «경계 넣기»는 쪽·행·글자를 숫자로 적는다(D-092 «남은 것»). 원본 이미지 위에서
**마우스로 찍은 자리**를 경계로 삼는 것이 사용자가 원하는 형태다.

- 왜 어렵지 않은가: 반대 방향은 이미 있다 — 내용 트리가 경계의 `anchor.bbox`를
  «캔버스 폭 / L2 `image_width`» 비율로 환산해 시작 행 점선을 그린다
  (`contents-tree.js` `anchor-overlay`). 필요한 것은 그 환산의 역이다.
- 경로: 캔버스 클릭 좌표 → L2 픽셀(같은 비율의 역수, 배율은 2.0 하드코딩이 아니라
  그 쪽의 L2 `image_width`로 — D-087) → 그 점을 품는 L2 행 bbox → `(page, line_index)`
  → 행 안 글자 오프셋(세로쓰기는 `(y - top) / 글자높이`, 글자높이는 행 길이 ÷ 글자 수).
  그다음은 이미 있는 `POST …/boundaries`(쪽·행·글자·깊이·역할).
- 정확도의 한계: 오프셋은 L2 행의 글자 간격이 고르다는 가정이다. 협주·부기가 섞인 행은
  한두 자 어긋날 수 있으니, 찍은 자리를 «확정»으로 넣지 말고 앵커 글자 몇 자를 미리
  보여 주고 ▲▼로 다듬게 한다.
- 함께 볼 것: 교정 텍스트에서 글자를 눌러 넣는 편집기(같은 API를 쓴다). 이미지 쪽이
  먼저인 이유는 고서 읽기가 이미지 중심이기 때문.
